# 1. Purpose

Phase 11.50 creates the smallest stable backend interface required for first-party clients — especially CMMChat — to consume the already-closed CMM OS application and conversational boundaries without duplicating backend logic or taking ownership of execution authority.

The phase is intentionally narrower than the broad historical roadmap wording for “Reusable Backend Interfaces”.

It does **not** implement every possible external interface.

The immediate objective is:

```text
CMMChat / first-party client
        ↓
stable reusable client backend interface
        ↓
canonical ConversationService
        ↓
canonical ApplicationGateway
        ↓
canonical Orchestrator and existing platform owners
```

The interface is a facade/adapter, not a new backend authority.

Canonical adapter package:


It already provides:


## 3.3 Phase 11.5 Conversational Interface

## 3.4 Phase 11.21 Model Gateway

Canonical model-call boundary:

```text

```

It owns:

```text
provider-independent model execution

structured output
```

```text

```

and the Phase 11.21 frozen design explicitly required the later 11.50 slice to inspect and adapt the Phase 11.3/11.5 boundaries rather than create a second backend.


The existence of the closed Phase 11.21 Model Gateway does **not** by itself prove those features are end-to-end reachable through `ConversationService`.

Phase 11.50 must not silently upgrade them.

# 4. Scope ruling

Phase 11.50 implements only:

```text
one reusable, versioned, client-facing backend interface
for first-party clients
over the existing canonical ApplicationGateway + ConversationService
```

It is the stable seam CMMChat can consume later.

It does not create a new execution system.

---

# 5. New authority ruling

Phase 11.50 introduces **no new business or execution authority**.

The only new object may be a thin client-backend facade whose authority is exactly:

```text
validate its own client-interface contract
delegate to canonical existing owners
project safe stable client-facing results
report capability truth
```

It must not own:

```text
sessions
conversation state
message history
orchestration
routing
model selection
model execution
provider dispatch
validation
approval
permissions
privacy
memory
knowledge
tools
workflows
operations
files
attachments
auth
billing
budgets
audit persistence
event storage
```

```text
      ↓
cmm/client_backend
      ↓

      ↓

      ↓

```

and separately, where existing canonical composition already exposes facts:



# 8. Canonical facade

The central object is:

```text
ClientBackend
```

or an equivalently precise name approved by the implementation plan.

It is a concrete facade over:

```text
ConversationService
ApplicationGateway
```

It may also consume read-only canonical capability declarations supplied at construction.

It must not instantiate its own canonical owners internally.

---

# 9. Required owner identity

Construction must require the exact official owner types.

At minimum:

```text
ConversationService
ApplicationGateway
```

If the facade receives both, their relationship must be coherent.

The client facade must not accept arbitrary duck-typed replacements in production simply because they have similarly named methods.

Official in-memory implementations remain valid for tests through the canonical construction path.

---

# 10. Client interface version

Introduce exactly one Phase 11.50 client-interface version constant:

```text
CLIENT_BACKEND_INTERFACE_VERSION="1"
```

This version identifies the facade contract only.

It does not replace:

```text
APPLICATION_API_VERSION
ModelGateway contract versions
Conversation contract serialization
HTTP/OpenAPI versioning
```

Version mismatch must fail closed.

---

# 11. Contract reuse rule

Do not invent duplicate message, session, response, stream or error DTOs where canonical contracts already exist.

The Phase 11.50 interface must reuse exact existing values whenever possible:

```text
ConversationMessage
AssistantResponse
ConversationCapabilityState
ApplicationResponse
ApplicationSession
ApplicationCapability
ApplicationStreamEvent
```

A Phase 11.50 contract may wrap these only when needed for:

```text
client-interface version
operation identity
correlation/request identity
safe capability manifest
```

No semantic copy of an existing canonical value is allowed.

---

# 12. Client request envelope

If one generic client envelope is required, it must be narrow.

Allowed fields:

```text
interface_version
request_id
operation
payload
```

The `payload` must contain canonical values or safe serialized forms of canonical values.

Do not create a second message schema.

Do not create a second session schema.

Do not create a second error hierarchy if existing public errors can be projected safely.

---

# 13. Supported Phase 11.50 operations

The minimum first-party client operations are:

```text
capabilities
create_session
get_session
load_conversation
submit_message
edit_message
regenerate_response
cancel_request
```

Each operation must delegate to an existing owner.

No operation may perform canonical work itself.

---

# 14. Session operations

Session operations delegate to the existing application/session boundary.

Phase 11.50 owns no session persistence.

Required:

```text
create_session -> canonical session/application service
get_session -> canonical session/application service
```

Session revision semantics remain canonical.

No hidden retry on concurrency conflict.

---

# 15. Conversation operations

Conversation operations delegate to the exact canonical `ConversationService`.

Required:

```text
load_conversation -> ConversationService.load
submit_message -> ConversationService.submit
edit_message -> ConversationService.edit
regenerate_response -> ConversationService.regenerate
cancel_request -> ConversationService.cancel
```

The facade must not reimplement edit/regenerate lineage semantics.

---

# 16. CMMChat relationship

CMMChat is a first-party client.

CMMChat must not become:

```text
session authority
conversation authority
routing authority
model execution authority
provider authority
privacy authority
approval authority
validation authority
```

CMMChat consumes the reusable interface.

No CMMChat source code is modified in Phase 11.50.

No dependency from CMM OS core packages back toward CMMChat is permitted.

---

# 17. Model Gateway relationship

Phase 11.50 must not expose the raw `ModelGateway` as a client escape hatch.

Forbidden:

```text
client_backend.model_gateway.execute(...)
client_backend.raw_model_gateway
client-provided provider adapter
client-side fallback authority
client-side routing policy
```

The Model Gateway remains an internal canonical execution boundary.

If the current application/conversation path does not yet reach model execution, Phase 11.50 reports that truth.

It does not bypass the Orchestrator to “make chat work”.

---

# 18. Reasoning effort

Phase 11.21 supports canonical reasoning effort at the model boundary.

Phase 11.50 does not yet claim reasoning effort is end-to-end reachable from CMMChat.

The client capability manifest must distinguish:

```text
model_boundary.reasoning_effort = available
conversation_end_to_end.reasoning_effort = unavailable/deferred
```

unless implementation inspection proves an existing canonical E2E path.

No new reasoning setting is smuggled into generic metadata.

---

# 19. Multimodal input

Phase 11.21 supports real image and document bytes at the model boundary.

Phase 11.5 currently exposes attachment references and no file authority.

Therefore Phase 11.50:

```text
does not create file upload
does not fetch arbitrary paths
does not fetch URLs
does not invent attachment storage
does not convert filename refs into fake multimodal input
```

Capability truth must distinguish:

```text
model_boundary.multimodal = available
conversation_end_to_end.multimodal = unavailable/deferred
document_upload = unavailable
attachments = reference_only
```

until a later E2E bridge is explicitly designed.

---

# 20. Streaming

Existing layers expose two distinct truths:

```text
ModelGateway: provider token streaming available
Application/cmm.api: public response-event SSE available
ConversationService: response streaming currently degraded to response_event_stream
```

Phase 11.50 must preserve this distinction.

The facade may expose existing response-event streaming.

It must not relabel response-event streaming as token streaming.

Required manifest examples:

```text
response_event_stream=available
model_token_stream=model_boundary_only
conversation_token_stream=end_to_end_unavailable
```

A later targeted E2E slice may change this only after connected verification.

---

# 21. Cancellation

Phase 11.21 has model-call cancellation.

Phase 11.3/11.5 capability truth may still report request cancellation unavailable.

Phase 11.50 must not infer:

```text
ModelGateway cancellation exists
therefore ConversationService cancellation is available
```

It reports the effective existing application/conversation capability.

```text
ClientBackendCapabilities
```

It may expose:

```text

conversation_available

model_boundary_reasoning
model_boundary_multimodal
model_boundary_token_stream
end_to_end_reasoning
end_to_end_multimodal
end_to_end_token_stream
```

Use enums/closed values rather than ambiguous booleans where three-state truth is needed.

Recommended status vocabulary:

```text
AVAILABLE
DEGRADED
UNAVAILABLE
BOUNDARY_ONLY
```

No capability may be inferred from model/provider names.

---

# 23. Capability source of truth

The Phase 11.50 capability manifest must be built from injected canonical declarations.

At minimum reuse:

```text
ApplicationCapability
ConversationCapabilityState
```

For Model Gateway boundary-only facts, use explicit injected canonical capability evidence or exact platform service availability.

Do not inspect model names.

Do not inspect provider names.

Do not hard-code “OpenAI supports X”.

---

# 24. Errors

The interface must project safe public failures.

Prefer reuse/projection from:

```text
ApplicationError
ConversationErrorCode
```

Phase 11.50 may introduce only client-interface-specific errors such as:

```text
UNSUPPORTED_INTERFACE_VERSION
INVALID_CLIENT_OPERATION
INVALID_CLIENT_CONTRACT
```

Do not duplicate:

```text
POLICY_DENIED
APPROVAL_REQUIRED
CANCELLED
CONFLICT
NOT_FOUND
CAPABILITY_UNAVAILABLE
```

when canonical layers already own them.

---

# 25. Error safety

Never expose:

```text
raw exception repr
stack trace
credentials
provider secrets
raw sensitive context
hidden reasoning
internal filesystem paths
internal object repr
```

Unknown internal failures map to one safe generic client error.

---

# 26. Serialization

Every Phase 11.50 public wrapper must:

```text
serialize deterministically
use primitive-safe values
reject unknown required enum values
reject unsupported interface versions
preserve canonical IDs verbatim
preserve canonical timestamps verbatim
preserve canonical revision values verbatim
```

No lossy rewriting of canonical identities.

---

# 27. Idempotency

Phase 11.50 must not introduce a second idempotency repository.

Where client operations map to existing idempotent application commands, reuse the canonical application idempotency seam.

Conversation edit/regenerate semantics remain owned by `ConversationService`.

---

# 28. Concurrency

No global client concurrency system.

Preserve exact canonical expected-revision behavior.

Conflicts remain conflicts.

Do not silently retry with a new revision.

---

# 29. HTTP / REST

The existing `cmm.api` HTTP/OpenAPI/SSE adapter remains canonical Phase 11.3 infrastructure.

Phase 11.50 may test that it remains reusable.

Phase 11.50 does **not** add a second REST server.

New external REST adapter expansion is deferred to Phase 11.51.

---

# 30. MCP / Actions

Explicitly out of scope:

```text
MCP server
OpenAI Actions endpoints
Claude-specific adapter
ChatGPT-specific adapter
external automation adapters
```

These belong to Phase 11.51.

---

# 31. CLI

The canonical CLI was closed in Phase 11.4.

Phase 11.50 does not add or modify CLI commands.

The CLI may later consume the same reusable client facade only if separately justified.

---

# 32. Event subscriptions

Phase 11.50 does not introduce a new event bus or subscription runtime.

Existing response-event streaming may be adapted.

General event subscriptions remain deferred.

---

# 33. Authentication / authorization

Phase 11.50 does not invent an auth system.

Where canonical permission/authorization decisions exist downstream, they remain authoritative.

If no client authentication owner exists, the reusable interface must not claim one.

External authentication belongs with external adapters/deployment work.

---

# 34. Routing

No Phase 11.35 routing-policy intelligence.

The client cannot rank providers/models.

The client cannot choose fallback.

The client cannot inject routing policy.

Explicit model preferences are not added to the CMMChat-facing interface in this phase unless an already-existing canonical application/conversation contract supports them exactly.

---

# 35. Validation

Phase 11.50 does not create a validation system.

Existing validation decisions stay downstream.

The facade validates only its own interface shape and version.

---

# 36. Budgets / cost

No Phase 11.38 cost-management system.

If canonical cost/usage evidence is already present in a safe response, it may be projected.

No client-side budget authority is introduced.

---

# 37. Audit

No Phase 11.44 persistent model-usage audit.

Existing canonical audit/evidence references may be projected if safe.

No new audit store.

---

# 38. Local-first behavior

The reusable interface must be independently testable without external network access.

Use official in-memory/canonical implementations.

No live provider or internet dependency in acceptance.

---
