## 1. Purpose

Remediation V5 exists only to close the two findings reported by Independent Re-audit V5:

- `MAJOR-V5-01` — a registered `ProviderConnection` whose exact provider authority is stale can still authorize an external administrative discovery client call before the coordinator eventually fails closed during capture/persistence;
- `MAJOR-V5-02` — the connection-level temporal guard introduced in Remediation V4 uses only route `last_seen_at`, but some durable discovery transitions do not advance that timestamp. An older snapshot can therefore be accepted after a newer state-changing pass and can restore stale route availability.

No other behavior may be redesigned or reopened.

Remediation V5 must preserve every finding already independently verified as remediated, including:

- `MAJOR-V4-01` — exact item-level provider/connection authority binding and stale-state capture rejection;
- `MAJOR-V4-02` — acceptance-time `ConnectionProposal` authority revalidation;
- `MAJOR-V4-03` — exact active canonical discovery manifest requirement;
- Remediation V3 exact component-graph identity;
- Remediation V3 durable `route.refreshed` persistence and rollback;
- V3 same-timestamp true no-op behavior;
- V2 auth-only isolation for Codex, Claude Code and Antigravity;
- V2 ownership-safe onboarding;
- the dedicated Phase 11 requirements matrix and `F11-014`;
- administrative, non-inference discovery;
- raw-secret boundary protections;
- CMM Usage deferral;
- CMMChat deferral;
- no Phase 11.35 implementation.

## 2. Authoritative V5 evidence

### 2.1 `MAJOR-V5-01`

A canonical provider/manifest/connection graph was created under ProviderSpec A.

Then:

```text
remove ProviderSpec A
register ProviderSpec B with the same provider_id
register a fresh active manifest B
leave the accepted connection from A in ProviderConnectionRegistry
```

The V4 exact authority binding correctly reports:

```text
CONNECTION_BOUND_CURRENT=False
```

But coordinator discovery currently behaves:

```text
STALE_CONNECTION_DISCOVERY_REJECTED=True
STALE_CONNECTION_EXCEPTION=
  ProviderStateCoherenceError
  connection x:main is bound to a stale or missing ProviderSpec

STALE_CONNECTION_CLIENT_CALLS=1
STALE_CONNECTION_ROUTES=()
STALE_CONNECTION_REVISION=0
STALE_CONNECTION_AUDIT=()
STALE_CONNECTION_REPOSITORY=None
```

Thus the eventual fail-closed persistence boundary works, but the external administrative discovery client has already been called.

### 2.2 `MAJOR-V5-01` route boundary

The same stale connection can also currently authorize a new route registration:

```text
CONNECTION_BOUND_CURRENT=False
ROUTE_REGISTER_ACCEPTED=True
ROUTE_BOUND_CURRENT_CONNECTION=True
```

This confirms that exact registration identity alone is not sufficient to authorize creation of a new route relation when the parent connection is no longer bound to the current provider authority.

### 2.3 `MAJOR-V5-02`

Canonical setup:

```text
activation_allowlist=("a",)

T0 = 01:00
TM = 01:30
T1 = 02:00
```

#### Pass T0

Provider advertises:

```text
a
b
```

Result:

```text
a -> available=True,  last_seen_at=T0
b -> available=False, last_seen_at=T0
revision=1
```

#### Pass T1

Provider advertises only:

```text
b
```

`a` becomes unavailable.

Because `b` is already deferred by the allowlist, no route observation advances.

Result:

```text
a -> available=False, last_seen_at=T0
b -> available=False, last_seen_at=T0
revision=2
```

The route-only temporal floor remains:

```text
ROUTE_LAST_SEEN_FLOOR=T0
```

But the persisted audit correctly records:

```text
route.unavailable a @ T1
```

and therefore:

```text
AUDIT_DISCOVERY_FLOOR=T1
COMBINED_DISCOVERY_FLOOR=T1
TM_IS_OLDER_THAN_COMBINED_FLOOR=True
```

Current implementation still accepts TM:

```text
STALE_TM_REJECTED=False
STALE_TM_CLIENT_CALLS=1
AFTER_TM_REVISION=3
a -> available=True, last_seen_at=TM
```

### 2.4 Restart stability

The exact T1 persistent state was restored into fresh canonical components.

After restart:

```text
RESTORED_ROUTE_LAST_SEEN_FLOOR=T0
RESTORED_AUDIT_DISCOVERY_FLOOR=T1
RESTORED_COMBINED_DISCOVERY_FLOOR=T1
RESTART_TM_IS_OLDER_THAN_COMBINED_FLOOR=True
```

Current implementation nevertheless still accepts TM:

```text
RESTART_STALE_TM_REJECTED=False
RESTART_STALE_TM_CLIENT_CALLS=1
RESTART_FINAL_REVISION=3
```

This proves the existing audit log contains the restart-stable temporal evidence needed to close `MAJOR-V5-02` without a new persisted field, store or schema version.

## 3. Architectural principle

Remediation V5 must close both findings by strengthening existing operation boundaries.

It must not introduce another authority or persistence concept.

Approved corrective model:

```text
resolve canonical registered connection
→ prove connection's provider authority is still current
→ prove manifest authority is current
→ derive latest durable connection discovery snapshot
→ reject stale snapshot before external client call
→ only then perform administrative discovery/reconciliation
```

For routes:

```text
new route relation
→ require current registered connection
→ require that connection is still bound to current ProviderSpec
→ bind route to the existing registration identity
```

The existing persisted audit history is reused as a temporal authority source.

No new durable watermark is introduced.

## 5. `MAJOR-V5-01` — discovery must revalidate connection authority before I/O

### 5.1 Canonical ordering

`ProviderRegistryStateCoordinator.discover_models()` must enforce this order:

```text
1. input type / datetime-awareness validation
2. resolve canonical registered connection by connection_id
3. require registered connection is still bound to current ProviderSpec
4. resolve active canonical manifest from registered.provider_id
5. require exact active manifest identity
6. derive latest durable discovery snapshot floor
7. require seen_at >= durable floor
8. call discovery client
9. reconcile routes
10. derive audit records
11. capture state
12. repository save
13. publish revision/audit
```

The external client must not be called before steps 2–7 succeed.

### 5.2 Connection authority check

After:

```python
registered = self._connections.get(connection.connection_id)
```

require:

```python
self._connections.is_bound_to_current_provider(registered)
```

If false:

```text
raise ProviderStateCoherenceError(
    "connection <id> is bound to a stale or missing ProviderSpec"
)
```

Use the same deterministic wording already established in:

- capture-time connection validation;
- connection-status transition validation.

Do not introduce a new exception class.

### 5.3 Caller-supplied connection object

The canonical registered connection remains the authority.

If the caller passes a stale/equal-value object while the registry contains a canonical registration, preserve the existing V4 contract for how the coordinator canonicalizes the value.

The new V5 guard applies to the canonical registered connection, not merely the caller object.

### 5.4 Guard before manifest lookup and client call

The binding guard should occur before active manifest resolution.

Reason:

```text
stale connection authority
```

is already sufficient to reject the operation.

Do not consult additional provider metadata or external services once the parent connection authority is invalid.

## 6. Route creation boundary under stale provider authority

### 6.1 Problem

`ModelRouteCatalog` currently validates that:

```text
connection_id
```

maps to an active connection registration.

But a connection registration can remain present while its own provider binding is stale.

Creating a new route under that connection establishes a new relation using an authority that should no longer authorize new work.

### 6.2 Approved design

Route creation/restoration paths that establish a new route-to-connection binding must require:

```text
connection exists in ProviderConnectionRegistry
AND
connections.is_bound_to_current_provider(connection) is True
```

Only then may the route bind to the current connection-registration identity.

### 6.3 Scope of the guard

Apply the guard to boundaries that create a new binding:

```text
ModelRouteCatalog.register(...)
```

and any restore path that creates a route binding from serialized state rather than reinstating an already-captured rollback snapshot.

Implementation must inspect:

```text
restore(...)
restore_all(...)
```

and distinguish:

- canonical persistent reconstruction;
- in-memory rollback restoration of already-existing route/binding state.

Do not accidentally make rollback unable to restore the exact pre-operation route state.

### 6.4 Error class

Do not introduce a dependency cycle solely to use `ProviderStateCoherenceError` inside `model_routes.py`.

Reuse the existing local route/connection referential-validation error contract already used when a referenced connection is absent or invalid.

The implementation plan must inspect the exact existing exception class/message and freeze the narrowest compatible behavior.

### 6.5 No automatic cleanup

A stale accepted connection remains visible.

Existing routes remain visible.

Capture continues to fail closed.

V5 only prevents stale authority from authorizing:

- external discovery I/O;
- creation of new route bindings.

Do not cascade-delete connection/routes.

## 8. `MAJOR-V5-02` — durable discovery watermark

### 8.1 Why route `last_seen_at` is insufficient

`last_seen_at` means:

```text
last discovery pass in which this provider model was observed
```

It does not mean:

```text
last successful connection-level discovery snapshot
```

These concepts diverge for:

- route disappearance;
- repeated allowlist deferral;
- transitions where availability changes but no provider model is marked seen.

Therefore:

```text
max(route.last_seen_at)
```

alone cannot provide the connection-level monotonic discovery floor.

### 8.2 Reuse existing durable evidence

The existing Provider Registry audit log is persisted and restored.

The relevant discovery-derived route events are exactly:

```text
route.discovered
route.unavailable
route.restored
route.refreshed
```

Each record already contains:

```text
occurred_at
detail.connection_id
```

and belongs to a persisted revision.

No new audit event is required.

## 9. Durable discovery snapshot floor

Introduce a private coordinator helper conceptually equivalent to:

```python
_latest_discovery_snapshot_at(connection_id: str) -> datetime | None
```

It derives two candidate floors.

### 9.1 Route observation floor

For existing routes of the connection:

```text
route_floor =
    max(route.last_seen_at)
```

ignoring absent/`None` values if the current route contract permits them.

### 9.2 Persisted audit floor

From the coordinator's persisted/restored audit log, select records satisfying all:

```text
record.event_type in {
    "route.discovered",
    "route.unavailable",
    "route.restored",
    "route.refreshed",
}

dict(record.detail).get("connection_id") == connection_id
```

Then:

```text
audit_floor =
    max(record.occurred_at)
```

### 9.3 Combined floor

Return:

```text
max(route_floor, audit_floor)
```

over the non-null candidates.

If neither exists:

```text
None
```

### 9.4 Exact event allowlist

Do not infer discovery chronology from arbitrary audit records.

Do not include:

```text
provider.connected
provider.validation_changed
connection.accepted
credential events
profile events
future unrelated event types
```

unless a future independently designed phase explicitly changes the contract.

V5 uses an explicit route-event allowlist only.

## 10. Temporal admission rule

After canonical connection and manifest validation and before client call:

```python
latest = self._latest_discovery_snapshot_at(registered.connection_id)
```

If:

```python
latest is not None and seen_at < latest
```

raise:

```text
ProviderStateCoherenceError(
    "discovery seen_at precedes current route state"
)
```

The existing message may be retained if already canonical.

### 10.1 Equality

If:

```text
seen_at == latest
```

the operation is allowed.

Preserve V3/V4 same-timestamp semantics.

A true no-op remains:

```text
no revision
no audit append
no repository save
```

### 10.2 No existing floor

If there is neither route observation nor relevant audit history for the connection:

```text
latest = None
```

Any otherwise-valid aware `seen_at` is allowed.

## 11. Restart stability

The watermark must survive restart without additional state.

The canonical restore path already restores:

```text
routes
revision
audit_log
```

After restart:

```text
_latest_discovery_snapshot_at(connection_id)
```

must derive the same effective latest durable snapshot time from restored state.

No in-memory-only watermark is sufficient.

No cache may be the sole source of truth.

If an optimization cache is ever introduced, it must be reconstructible from routes/audit and non-authoritative.

Remediation V5 should not introduce one unless necessary.

## 15. Preserve no-op semantics

Do not introduce a durable record for every successful discovery scan.

Specifically, do not add:

```text
discovery.snapshot
```

for true no-op scans.

The existing semantics remain:

```text
no canonical state change
→ no revision
→ no audit record
→ no repository save
```

V5 uses persisted history only to prevent a stale snapshot from superseding already-durable state.

## 16. Preserve audit sanitation

The V5 temporal helper reads only:

```text
event_type
occurred_at
detail.connection_id
```

Do not add:

- model-list payloads;
- raw provider responses;
- credentials;
- auth values;
- endpoint secrets;
- environment paths.

Existing sanitized route event detail remains sufficient.

## 17. Event-record completeness invariant

Every durable connection-route mutation produced by coordinator discovery must continue to emit at least one relevant route audit record at the discovery `seen_at`.

Relevant mutation classes:

```text
new route
→ route.discovered

available -> unavailable
→ route.unavailable

unavailable -> available
→ route.restored

available -> available with last_seen advance
→ route.refreshed
```

Remediation V5 must not create a new durable discovery mutation class that changes route state without leaving temporal audit evidence.

The implementation review must explicitly verify this invariant.

## 18. Interaction with V4 exact bindings

Before deriving the audit/route temporal floor:

```text
registered connection must be current
manifest must be exact active canonical manifest
```

Therefore stale provider authority is rejected before temporal reasoning.

The temporal watermark does not become an authority substitute.

It only orders snapshots after canonical authority is established.
