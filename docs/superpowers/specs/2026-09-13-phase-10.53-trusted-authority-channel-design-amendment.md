# Phase 10.53 — Trusted Authority Channel Design Amendment

**Status:** Approved design amendment
**Phase:** 10.53 — Neurodivergence Domain
**Baseline HEAD:** `923909e7a71c0019b69ad0cd47e19ef9a507250b`
**Purpose:** Close the remaining clinical-authority boundary without creating Neurodivergence-local trust infrastructure.

---

## 1. Context

Phase 10.53 already has a working Neurodivergence Domain Pack with:

- exploratory model inference;
- working hypotheses;
- balanced differential reasoning;
- canonical cross-domain permissions;
- proposal-first sensitive memory;
- `SENSITIVE` privacy;
- canonical Knowledge Package integration;
- anti-fragmentation protections.

The remaining problem is narrower:

```text
caller-authored metadata
```

must never be able to manufacture:

```text
authoritative permission
authoritative Health status
```

even when that metadata copies the serialized shape of canonical objects.

The prior V3 implementation attempt was reverted.

The current repository baseline is intentionally the V2 implementation plus
Audit V1 and Re-audit V2 evidence.

---

## 2. Frozen product semantics

This amendment does not change the approved user-facing behavior.

The following remain mandatory:

```text
EXPLORATORY_MODEL_INFERENCE=ALLOWED
ASSOCIATION_AND_PATTERN_REASONING=ALLOWED
WORKING_HYPOTHESES=ALLOWED
DIFFERENTIAL_REASONING=BALANCED_NOT_ADVERSARIAL
NEGATIVE_EVIDENCE=PROPORTIONATE_NOT_ROUTINE
DISCLAIMER_SPAM=PROHIBITED_AS_DEFAULT_BEHAVIOR
```

A model may explore:

- possible associations;
- possible explanations;
- overlaps;
- longitudinal patterns;
- competing hypotheses;
- differential reasoning.

A model may not promote those observations to an authoritative clinical status.

The strict boundary belongs at:

```text
clinical status promotion
sensitive persistence
cross-domain authority
external action
```

---

## 3. Threat model

The protected boundary is:

```text
untrusted request / caller metadata
    versus
trusted in-process canonical runtime/orchestrator state
```

This amendment does not attempt to defend against arbitrary malicious Python
code already executing inside the trusted runtime process.

The trusted computing base includes the canonical:

- reasoning runtime;
- domain orchestrator/integration layer;
- permission resolver/gate;
- approval service;
- authoritative source-domain logic.

The invariant is:

> Caller-controlled JSON or metadata must never be sufficient to create authority.

Serialization is not authority.

Shape is not provenance.

A decision ID string is not authority.

A boolean is not authority.

A caller-authored object reconstructed from JSON is not authority merely because
it uses a canonical dataclass constructor.

---

## 4. Architectural decision

Phase 10.53 adopts a shared **trusted authority channel** for reasoning.

`ReasoningRuleContext.metadata` remains:

```text
JSON-safe
portable
non-authoritative
caller-influenced / request-derived
```

A separate runtime-only channel carries trusted authority:

```text
ReasoningRuleContext
├── metadata
│   └── never grants authority
└── authority_context
    └── trusted runtime/orchestrator-only authority
```

The exact canonical shared contract is named:

```text
ReasoningAuthorityContext
```

The exact repository location may follow the existing Cognitive Layer contract
layout, but ownership is shared Cognitive/Reasoning infrastructure, not the
Neurodivergence Domain Pack.

---

## 5. Core invariant

No combination of values inside:

```text
ReasoningRuleContext.metadata
```

may by itself or collectively cause:

```text
HYPOTHESIS -> CONFIRMED
IN_EVALUATION -> CONFIRMED
HYPOTHESIS -> RULED_OUT
IN_EVALUATION -> RULED_OUT
```

for a clinical claim.

Authoritative transitions require an applicable trusted entry inside:

```text
ReasoningRuleContext.authority_context
```

---

## 6. `ReasoningAuthorityContext`

`ReasoningAuthorityContext` is a runtime-only typed contract.

It is not a general-purpose registry.

It is not persistent storage.

It is not a resolver.

It is not a new permission engine.

It is not a Health database.

It is a bounded set of authority facts already resolved by canonical owners for
the current reasoning execution.

Conceptually it contains two kinds of trusted evidence:

```text
permission authority
source-domain authority
```

The implementation should reuse existing canonical types where dependency
direction permits.

Where direct reuse would create an invalid dependency cycle, the shared
Reasoning Layer may define the smallest neutral typed projection required by
reasoning.

Such a projection must be constructed only by canonical integration/runtime
code after real authority evaluation.

---

## 7. Permission authority

Current cross-domain permission authority remains owned by:

```text
DomainPermissionResolver
DomainPermissionGate
ApprovalService
```

The trusted reasoning channel may carry the effective result of that canonical
evaluation.

It must preserve enough binding to establish that the authority applies to the
current:

```text
actor
session
source domain
target domain
resource
purpose
effective gate outcome
approval state when applicable
```

A caller-supplied mapping such as:

```text
permission_authority=True
```

or:

```text
{
  "decision_id": "...",
  "outcome": "allow"
}
```

must have zero authority.

Likewise, reconstructing a `PermissionGateResult` from caller JSON does not
prove that the gate executed.

---

## 8. Health authority

Health remains the sole owner of clinical diagnostic status.

Neurodivergence must not duplicate Health diagnostic truth logic.

The trusted reasoning channel may carry an authoritative Health-derived clinical
claim only after the canonical Health owner has established the applicable
status.

For confirmed clinical status, the Health owner must have established its own
definitive semantics.

Neurodivergence must not infer:

```text
documented == confirmed
```

and must not recompute Health's definitive-status rules locally.

A caller-authored mapping such as:

```text
{
  "is_definitive": true,
  "may_present_as_definitive": true
}
```

has zero authority.

---

## 9. Cross-domain transfer remains necessary but not sufficient

`CrossDomainContextTransfer` remains the canonical carrier for admitted
cross-domain information.

A transfer is not itself authority.

The final positive clinical transition requires both:

```text
1. the information was admitted through the current canonical permission path;
2. the clinical claim is represented in the trusted authority channel as
   authoritative under Health ownership.
```

A structurally valid transfer with no trusted authority context must not promote
clinical certainty.

---

## 10. Provenance

The trusted authority channel must preserve source identity and provenance.

At minimum, authoritative source-domain evidence must remain bound to:

```text
source domain
resource / claim identity
purpose
source provenance
current execution context
```

The exact representation should reuse existing canonical provenance contracts
where possible.

Caller-supplied provenance metadata is informational only unless canonical
runtime code has promoted the corresponding fact into the trusted authority
channel.

---

## 11. Construction boundary

`ReasoningAuthorityContext` must be constructed by trusted canonical
runtime/integration code.

The preferred construction point is the existing reasoning/domain integration
path that creates `ReasoningRuleContext`.

The construction flow is:

```text
request / session
    ↓
canonical domain orchestration
    ↓
permission resolution
    ↓
DomainPermissionGate
    ↓
ApprovalService when required
    ↓
source-domain authoritative evaluation
    ↓
ReasoningAuthorityContext
    ↓
ReasoningRuleContext.authority_context
    ↓
ReasoningRule evaluation
```

The implementation must not populate `authority_context` directly from
request metadata.

---

## 12. Default behavior

The new field must be optional:

```text
authority_context=None
```

for reasoning executions that do not require authority.

Existing ordinary reasoning rules must continue to work without a trusted
authority context.

Absence of `authority_context` means:

```text
no authoritative promotion
```

not:

```text
reasoning failure
```

This preserves exploratory behavior.

---

## 13. Serialization boundary

`metadata` remains JSON-freezable/serializable.

`authority_context` is runtime-only and is not treated as ordinary JSON
metadata.

It must not be silently included in generic caller-facing serialization.

If the current reasoning contracts provide a serialization method, the trusted
authority channel must either:

- be excluded from untrusted/request serialization; or
- serialize only as non-authoritative diagnostic/reference information that
  cannot be rehydrated into authority by an external caller.

Rehydrating caller-supplied JSON must not restore trusted authority.

---

## 14. Neurodivergence consumption

The Neurodivergence certainty rule may inspect:

```text
context.authority_context
```

only for authoritative transitions.

It may continue to inspect ordinary `metadata` for:

- requested transition;
- exploratory evidence;
- presentation hints;
- non-authoritative observations;
- provenance references for display/audit.

However:

```text
metadata -> authority
```

is forbidden.

For clinical `CONFIRMED`, the rule must require applicable:

```text
trusted permission authority
+
trusted Health clinical authority
```

For authoritative `RULED_OUT`, the rule must require an existing canonical
Health-owned negative/definitive authority path.

If no such Health canonical negative verdict exists, `RULED_OUT` remains
fail-closed.

No new negative-diagnosis subsystem is introduced by this amendment.

---

## 15. Shared applicability

The channel is shared infrastructure because the same authority distinction may
matter to other domains.

Potential future consumers include:

```text
Mental Health
University
Relationships
other sensitive first-party domains
```

This amendment does not require those domains to migrate during Phase 10.53.

Phase 10.53 only introduces the smallest shared contract necessary and connects
Neurodivergence.

No unrelated domain behavior is changed.

---

## 16. Anti-fragmentation

Forbidden:

```text
NeurodivergenceAuthorityRegistry
NeurodivergenceAuthorityResolver
NeurodivergenceAuthorityStore
NeurodivergencePermissionEngine
NeurodivergenceClinicalAuthority
NeurodivergenceTrustedContext
HealthAuthorityRegistry
ReasoningAuthorityStore
```

unless an already-existing canonical component with that responsibility is
being reused.

The approved new concept is exactly one shared runtime contract:

```text
ReasoningAuthorityContext
```

plus the minimum integration required to populate it from existing canonical
owners.

No new persistent store is approved.

No new loader is approved.

No new registry is approved.

No new runtime is approved.

---

## 17. Compatibility

The change must preserve:

```text
existing ReasoningRule behavior when no authority is required
existing DomainPermissionGate behavior
existing ApprovalService lifecycle
existing CrossDomainContextTransfer contracts
existing Health rules
existing Knowledge Package behavior
existing memory behavior
existing privacy behavior
existing trace behavior
existing Phase 8/10 invariants
```

The authority channel is additive to the reasoning execution context.

It must not force all reasoning rules to become permission-aware.

## 18. TDD requirements

Implementation must begin with adversarial RED tests.

Minimum required adversarials:

### AT-AUTH-1 — metadata cannot forge permission authority

A caller supplies all metadata necessary to imitate:

```text
ALLOW
APPROVAL_CONSUMED
decision ids
approval ids
resource binding
purpose binding
```

without the canonical gate path.

Expected:

```text
clinical CONFIRMED blocked
```

### AT-AUTH-2 — metadata cannot forge Health authority

A caller supplies a Health-definitive-looking mapping without authoritative
Health ownership.

Expected:

```text
clinical CONFIRMED blocked
```

### AT-AUTH-3 — full combined metadata forgery

A caller supplies:

```text
canonical-looking permission metadata
canonical-looking transfer
canonical-looking provenance
canonical-looking Health definitive verdict
```

Expected:

```text
clinical CONFIRMED blocked
```

This is the central regression test.

### AT-AUTH-4 — trusted positive path

A real canonical flow produces:

```text
current permission authority
+
Health definitive authority
```

and the exact applicable transfer.

Expected:

```text
clinical CONFIRMED allowed
```

### AT-AUTH-5 — exploratory reasoning unaffected

No authority context exists.

Expected:

```text
working hypothesis still allowed
useful exploratory output still allowed
no disclaimer-only behavior
```

## 23. Non-goals

This amendment does not introduce:

- cryptographic signatures;
- process isolation;
- hostile-code protection inside the trusted Python runtime;
- a permission decision database;
- a Health clinical database;
- a generic distributed capability system;
- a new Knowledge Graph;
- a new memory store;
- Phase 11 behavior;
- migration of every existing domain to the new channel.

The scope is the smallest shared in-process authority boundary required by
Phase 10.53.

---

## 24. Approved architecture

The approved architecture is:

```text
caller / request
    ↓
metadata
    ↓
canonical orchestrator / integration
    ├─ DomainPermissionResolver
    ├─ DomainPermissionGate
    ├─ ApprovalService
    └─ authoritative source-domain evaluation
           ↓
    ReasoningAuthorityContext
           ↓
    ReasoningRuleContext
      ├─ metadata
      │    └─ non-authoritative
      └─ authority_context
           └─ trusted runtime-only authority
           ↓
    Neurodivergence certainty rule
           ↓
    authoritative transition only when trusted authority applies
```

This is the canonical design for the Phase 10.53 V3 redo.
