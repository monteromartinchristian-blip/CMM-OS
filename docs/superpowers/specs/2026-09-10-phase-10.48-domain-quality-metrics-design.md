## 1. Purpose

Phase 10.48 adds the canonical Domain Intelligence quality-policy layer. A Domain Pack may declare which quality dimensions matter, their relative weights, evaluator references, minimum scores and blocking semantics. Phase 10.48 also defines immutable evidence/result contracts and a pure deterministic assessment function over evidence already produced elsewhere.

Canonical ownership:

```text
Phase 10.47 = benchmark assets
Phase 10.48 = domain quality policy + deterministic aggregation
Phase 11.36 = model/evaluator execution + comparison + regression + rankings
Phase 11.35/11.36+ = routing from evaluation evidence
```

## 4. DP-048

`DP-048` establishes a declarative, domain-owned quality policy attached to `DomainDefinition` plus a pure assessment path:


This path performs validation and arithmetic only. It never runs an evaluator, benchmark, model or provider and never compares/ranks models.

## 6. Production contracts

### 6.1 DomainQualityMetric

```python
DomainQualityMetric(
    id="quality-metric:health:prudence",
    domain_id=DomainId(slug="health"),
    schema_version="1",
    version="1",
    name="prudence",
    weight=Decimal("0.20"),
    evaluator_id="evaluator:prudence",
    minimum_score=Decimal("0.85"),
    blocking=True,
    metadata={},
)
```

Rules:

- canonical ID: `quality-metric:<domain-slug>:<metric-slug>`;
- embedded slug must equal `domain_id.slug`;
- `DomainId` is reused; no competing identifier type;
- `schema_version` versions serialization;
- `version` versions policy;
- `name` is a stable extensible dimension string, not a closed enum;
- `weight` is finite `Decimal`, `0 < weight <= 1`;
- `evaluator_id` is an opaque non-empty reference only;
- `minimum_score` is finite `Decimal` in `[0,1]`;
- `blocking` is strict `bool`;
- metadata is immutable JSON-safe descriptive audit data and carries no provider/model/routing authority.

### 6.2 Weight normalization

Metric weights do not have to sum exactly to `1`. Aggregate scoring is:

```text
aggregate_score = Σ(score × weight) / Σ(weight)
```

This preserves relative priority without forcing every future metric addition to rebalance the full catalog. First-party catalogs should nevertheless normally sum to `1.00` for readability.

### 6.3 DomainQualityHumanReviewResult

Minimal typed review evidence:

```python
DomainQualityHumanReviewResult(
    id="quality-review:health:prudence:001",
    schema_version="1",
    status="accepted",
    score=Decimal("0.90"),
    confidence=Decimal("0.95"),
    reviewer_ref="reviewer:human",
    notes=("Prudence requirements preserved.",),
    metadata={},
)
```

`score`, `confidence` and `reviewer_ref` may be optional. The contract stores evidence only: no reviewer identity system, scheduling, approval workflow or external contact is implemented.

### 6.4 DomainQualityMetricResult

```python
DomainQualityMetricResult(
    metric_id="quality-metric:health:prudence",
    domain_id=DomainId(slug="health"),
    schema_version="1",
    metric_version="1",
    metric_name="prudence",
    score=Decimal("0.91"),
    weight=Decimal("0.20"),
    minimum_score=Decimal("0.85"),
    blocking=True,
    evaluator_id="evaluator:prudence",
    evaluator_version="3",
    confidence=Decimal("0.94"),
    human_review_results=(...),
    metadata={},
)
```

It snapshots the exact policy that applied and preserves metric value, weight, threshold, blocking flag, evaluator ID/version, confidence and human-review results.

Derived semantics:

```text
threshold_passed = score >= minimum_score
blocking_failure = blocking and not threshold_passed
```

### 6.5 DomainQualityAssessment

```python
DomainQualityAssessment(
    domain_id=DomainId(slug="health"),
    schema_version="1",
    metric_results=(...),
    aggregate_score=Decimal("0.91"),
    confidence=Decimal("0.93"),
    blocking_failures=(),
    passed=True,
    metadata={},
)
```

Rules:

- one unique result per declared metric;
- aggregate score is the normalized weighted mean of metric scores;
- assessment confidence is the normalized weighted mean of metric-result confidence;
- `blocking_failures` contains, in canonical declared order, each blocking metric whose score is below threshold;
- `passed=False` whenever `blocking_failures` is non-empty;
- otherwise `passed=True`;
- there is no separate global aggregate threshold in 10.48.

### 6.6 Pure helpers

Allowed:

```python
build_domain_quality_metric_result(...)
assess_domain_quality(...)
export_domain_quality_assessment(...)
import_domain_quality_assessment(...)
```

`build_domain_quality_metric_result` snapshots a metric definition into supplied evidence without executing anything.

`assess_domain_quality` requires exactly one result for every declared metric, rejects missing/extra/duplicate/stale/mismatched evidence, validates policy snapshots, computes aggregate score/confidence and derives blocking failures.

## 7. Decimal invariants

All quality numeric values use `Decimal`:

- weight;
- minimum score;
- metric score;
- result confidence;
- optional human-review score/confidence;
- aggregate score;
- assessment confidence.

Runtime constructors reject `float`, `int`, `bool` and numeric strings. Deserialization accepts canonical decimal strings emitted by serialization. Values must be finite; score/confidence/threshold are in `[0,1]`; weights satisfy `0 < weight <= 1`.

Canonical decimal serialization must be independent of the global decimal context and preserve high precision exactly. Tests must cover at least contexts with precision `10`, `28` and `50`.

## 8. Metadata authority boundary

Quality metadata is descriptive only. Reuse or equivalently enforce Phase 10.47's recursive normalized rejection of model/provider/routing authority keys, including semantic style/casing variants of:

```text
model, model_id, models, candidate_models, preferred_models, prohibited_models
provider, provider_id, providers, candidate_providers, preferred_providers, prohibited_providers
routing_weight, routing_weights
```

Only mapping keys are checked; prose values are not fuzzy-scanned. Contract-owned `weight`, `minimum_score`, `blocking`, `evaluator_id`, `evaluator_version`, `score` and `confidence` are allowed.

## 14. Validation

Fail closed on:

- malformed or domain-mismatched IDs;
- empty names/versions/evaluator IDs;
- duplicate metric/result IDs;
- invalid numeric types, NaN, Infinity, invalid ranges;
- non-strict booleans;
- non-JSON-safe/deeply mutable metadata;
- unknown serialized fields;
- model/provider/routing authority metadata;
- wrong-domain results;
- stale metric versions;
- mismatched evaluator IDs;
- result weights, thresholds or blocking flags differing from policy;
- missing or unexpected results;
- caller-controlled aggregate/blocking values inconsistent with canonical derivation.

No invalid metric/result is silently dropped.

## 15. Determinism

- first-party metric order is declared and deterministic;
- assessment emits metric results and blocking failures in declared metric order;
- metadata serialization uses stable key ordering;
- Decimal serialization is canonical/context-independent;
- identical policy + evidence yields equal assessments;
- canonical assessment export is byte-identical;
- core assessment creates no timestamps or random IDs.

## 19. AT-DP-048

- canonical `DomainRegistry`;
- real `ParsedDomainPack`/declarative path;

Required scenarios:

**A — canonical discovery:** `DomainRegistry -> DomainDefinition -> quality_metrics`.

**B — declarative round-trip:** real first-party quality metrics survive canonical Domain Pack parsing exactly.

**H — fail-closed binding:** missing, extra, wrong-domain, stale-version, altered-weight/threshold/blocking/evaluator evidence is rejected.

**I — observability isolation:** quality calculation does not use `DomainMetricMeasurement`, `DomainMetricsSnapshot` or `DomainMetricsCalculator`.

**J — Phase 11 boundary:** no model/provider/evaluator execution, benchmark scheduling, comparison, ranking, regression detection or routing exists in the production path.

## 27. Final design statement

Phase 10.48 is deliberately narrow:

> **A domain declares what quality means. External evaluation produces evidence later. Phase 10.48 validates and deterministically aggregates that evidence without executing anything.**

This preserves the 10.47 → 10.48 → 11.36 architecture and avoids every parallel registry, loader, resolver, store, runtime or engine.
