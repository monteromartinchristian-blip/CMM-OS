## 3. MAJOR-01 — Premium permission neutrality

### 3.1 Problem

`DomainModelPolicy` is intended to contribute objective inference requirements only.

However, the current domain adapter constructs a canonical `ModelRequirements` object whose `premium_allowed` field defaults to `False`.

The canonical requirements resolver then computes effective premium permission using restrictive boolean conjunction:

```python
premium_allowed = all(
    source.requirements.premium_allowed
    for source in ordered_sources
)
```

Therefore, a domain source that was intended to have no opinion on premium permission currently contributes an implicit denial.

That violates the approved ownership boundary.

The domain must not decide whether premium use is allowed.

---

## 4. Approved remediation for MAJOR-01

### 4.1 New provenance-level participation flag

Extend the canonical Agent Runtime source contract:

```python
ModelRequirementsSource
```

with:

```python
contributes_premium_permission: bool = True
```

This flag belongs to the source/provenance layer, not to `ModelRequirements`.

The meaning is:

```text
True
    This source participates in premium allow/deny composition.

False
    This source has no opinion about premium permission.
```

### 4.2 Backward compatibility

The default MUST be:

```python
contributes_premium_permission=True
```

Therefore all existing sources keep their current semantics unless they explicitly opt out.

No existing source must be silently reinterpreted.

### 4.3 Domain source behavior

The Phase 10.46 domain adapter MUST construct:

```python
ModelRequirementsSource(
    ...,
    contributes_premium_permission=False,
)
```

A domain source therefore abstains from premium permission composition.

### 4.4 Resolver behavior

The canonical resolver MUST compute premium permission only from participating sources:

```python
premium_sources = tuple(
    source
    for source in ordered_sources
    if source.contributes_premium_permission
)
```

Then:

```python
premium_allowed = (
    all(source.requirements.premium_allowed for source in premium_sources)
    if premium_sources
    else False
)
```

This preserves fail-closed semantics when no authoritative source grants premium permission.

### 4.5 Required semantic truth table

The following behavior is mandatory:

```text
authoritative source=True
+ neutral domain source
= True
```

```text
authoritative source=False
+ neutral domain source
= False
```

```text
neutral domain source only
= False
```

```text
adding/removing a neutral domain source
must not change premium permission
when authoritative sources already exist
```

### 4.6 Explicit non-solutions

Do NOT remediate MAJOR-01 by:

- setting domain `premium_allowed=True`;
- special-casing `source_kind == "domain"` in the resolver;
- changing `ModelRequirements.premium_allowed` to `bool | None`;
- adding a domain-specific premium resolver;
- adding user/provider logic into Domains;
- changing Kernel routing behavior;
- adding model/provider identifiers to DomainModelPolicy.

## 5. Why the participation flag is canonical

Premium permission is not a model capability.

It is an authority decision contributed by policy layers.

Therefore "does this source participate in premium permission composition?" belongs to source provenance, not model requirements themselves.

This preserves a clean three-state semantic model:

```text
participates + True  = ALLOW
participates + False = DENY
does not participate = NO OPINION
```

without changing the public boolean meaning of `ModelRequirements.premium_allowed`.

If `ModelRequirementsSource` is serializable today, the new field MUST round-trip.

Requirements:

- deterministic deserialization;
- unknown-field behavior preserved;
- existing serialized payloads with no field deserialize as `True`;
- existing source equality/hash/immutability behavior preserved.

The field must be included in public contract tests.

## 7. MAJOR-02 — Structural adapter must fail closed

### 7.1 Problem

To preserve the existing dependency-direction invariant, Agent Runtime cannot import `cmm.domains`.

The implementation therefore accepts a structurally compatible object instead of importing `DomainModelPolicy`.

The current validation only checks attribute presence.

That allows semantically invalid full-shape objects to bypass the strict `DomainModelPolicy` contract.

Examples currently accepted include:

```text
domain_id="not-a-domain-id"
require_reasoning="yes"
require_context_validation="false"
fallback_policy="not-a-fallback-policy"
metadata=None
```

This violates the fail-closed requirement.

---

## 8. Approved remediation for MAJOR-02

### 8.1 Keep the import boundary

The following invariant remains mandatory:

```text
cmm.agent_runtime MUST NOT import cmm.domains
```

Do not fix MAJOR-02 by importing the domain contract and using `isinstance`.

### 8.2 Structural seam remains allowed

The import-safe structural seam may remain, but it MUST perform strict semantic validation before constructing any canonical runtime contract.

### 8.3 Required validation surface

The adapter MUST validate all of the following.

#### Domain ID

The supplied `domain_id` must represent a canonical domain identifier.

At minimum:

```text
domain:<slug>
```

with a valid non-empty slug.

Use existing identifier syntax/conventions if a shared dependency-neutral validator already exists.

Do not import `cmm.domains`.

Do not duplicate large domain-ID infrastructure if a small canonical shared helper already exists.

#### Booleans

Every approved boolean field MUST satisfy:

```python
type(value) is bool
```

Do not accept truthy/falsy coercions.

The boolean fields are:

```text
require_reasoning
require_tool_calling
require_structured_output
require_json_mode
require_json_schema
require_vision
require_audio_input
require_audio_output
require_embeddings
require_context_validation
require_response_validation
```

#### Minimum context window

Allowed:

```text
None
int > 0
```

Forbidden:

```text
bool
0
negative integer
float
string
other types
```

#### Fallback policy

Allowed:

```text
None
canonical ModelFallbackPolicy
```

No duck-typed string or arbitrary object is accepted.

#### Metadata

Must be a real mapping compatible with the canonical adapter/contract expectations.

`None`, strings, lists, and arbitrary scalars are invalid.

#### Surface completeness

All required structural attributes must be present.

Missing fields fail closed.

## 9. Validation ownership

The runtime adapter's strict structural validation is a boundary guard, not a second domain contract implementation.

Its job is only to ensure that an import-safe object cannot smuggle values that violate the canonical DomainModelPolicy semantic surface.

Do not:

- add domain business logic;
- infer missing values;
- coerce invalid values;
- repair malformed policy objects;
- add provider/model rules;
- weaken errors to preserve permissive behavior.

Invalid structural inputs MUST raise the existing canonical Agent Runtime requirements-resolution error type or the smallest existing equivalent.
