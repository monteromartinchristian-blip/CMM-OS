# 5. MAJOR-01 design — AUTO must iterate canonical candidates through hard execution gates

## 5.1 Problem

Current AUTO flow:

```text
find_matching_models(...)
        ↓
first candidate passing gateway capability/modalities
        ↓
return candidate
        ↓
later preflight privacy/adapter checks
```

This can select a remote candidate that canonical privacy rejects and stop even when a later local candidate is executable.

## 5.2 Required architecture

AUTO must remain a thin consumer of the existing canonical selector.

Required flow:

```text
find_matching_models(...)
        ↓
ordered canonical candidates
        ↓
for candidate in canonical order:
    gateway hard-gate preflight(candidate)
        ├─ pass  -> select candidate immediately
        └─ candidate-local fail -> continue
        ↓
no candidate passes
        ↓
deterministic fail-closed error
```

The gateway MUST NOT:

```text
re-rank
score
optimize cost
prefer providers
learn preferences
run benchmark policy
invent Phase 11.35 behavior
```

The order returned by `find_matching_models(...)` remains authoritative.

## 5.3 Hard gates evaluated per AUTO candidate

Before AUTO selects a candidate, evaluate at minimum:

```text
provider exists
provider execution availability
model execution availability
requested reasoning effort
required capabilities
image/document modality support
streaming when required
canonical privacy for this candidate's provider
adapter existence/availability
```

If a candidate fails one of these candidate-local gates, AUTO continues to the next candidate in the canonical order.

## 5.4 Errors that must not be skipped as candidate-local

Malformed request-level failures remain terminal, including:

```text
invalid canonical request
invalid structured-output contract
invalid tool contract
invalid input part
cancelled request
internal invariant violation
```

AUTO iteration must not swallow arbitrary exceptions.

## 5.5 Deterministic exhaustion

If no canonical candidate is executable:

- fail closed;
- use an existing safe Model Gateway error;
- do not expose raw exception payloads;
- record safe exhaustion evidence;
- do not fabricate a new routing result.

The implementation may preserve candidate failure codes internally for observability, but no sensitive provider payload may be leaked.

## 5.6 Required tests

Add RED tests proving:

```text
AUTO + LOCAL_ONLY + canonical remote first + valid local second
=> local executes
=> remote adapter call count = 0
=> local adapter call count = 1

AUTO + first candidate missing adapter + valid second candidate
=> second executes

AUTO + first candidate lacks requested reasoning effort + valid second
=> second executes

AUTO + no executable candidate
=> deterministic fail-closed terminal result

AUTO order
=> exact canonical candidate order preserved
=> no gateway re-ranking
```

## 5.7 Acceptance integration

At least one AUTO/privacy adversarial scenario must be added to `AT-DP-121`.

# 6. MAJOR-02 design — cancellation belongs to the entire model call

## 6.1 Problem

The current fallback path invokes the fallback adapter with:

```text
cancellation=None
```

even when the original call already has a live cancellation token.

This permits work after the user has cancelled the call.

## 6.2 Required lifecycle

One model-call cancellation token must remain authoritative across:

```text
initial preflight
primary adapter attempt
transport retry
retry backoff
fallback planning
fallback candidate preflight
fallback adapter attempt
stream loop
terminal normalization
```

A fallback is a continuation of the same call, not a new call.

## 6.3 Mandatory cancellation checkpoints

Check the same token:

```text
before primary adapter invocation
after retryable primary failure
before retry/backoff
after retry/backoff
before fallback planning
before every fallback candidate
after fallback candidate preflight
before every fallback adapter invocation
before returning fallback success
```

If cancellation is effective at any checkpoint:

```text
MODEL_CALL_CANCELLED
```

becomes terminal.

## 6.4 Retry/fallback interaction

Cancellation wins over:

```text
retry
fallback
provider transport recovery
```

Once cancelled:

```text
no retry provider I/O
no fallback provider I/O
no success result
```

is permitted.

## 6.5 Required tests

RED tests:

```text
primary cancels token then raises retryable error
=> fallback_calls=0
=> terminal MODEL_CALL_CANCELLED

token cancelled during retry backoff
=> no next retry

token cancelled before fallback candidate preflight
=> no fallback adapter execution

fallback receives exact same cancellation object identity
```

## 6.6 Acceptance integration

`AT-DP-121` must combine cancellation and fallback in one connected scenario.

# 7. MAJOR-03 design — real public streaming deadline

## 7.1 Problem

The current stream loop:

```text
check deadline
next(adapter_events)
process returned event
```

cannot enforce timeout while `next()` blocks.

A provider may return a chunk after the deadline and the gateway can emit that chunk before noticing the timeout.

## 7.2 Required public semantic

The public Model Gateway stream deadline is authoritative.

After the deadline:

```text
no CONTENT_DELTA
no TOOL_CALL_DELTA
no USAGE
no COMPLETED
```

may be emitted as successful provider progress.

The only permitted terminal public outcome is the normalized timeout/error path.

## 7.3 Required bounded acquisition boundary

The gateway must not call potentially blocking provider iterator `next()` directly on the public consumer path without a deadline boundary.

Approved design:

```text
provider iterator
      ↓
single per-stream pump worker
      ↓
bounded queue
      ↓
public gateway iterator waits only remaining deadline
```

Equivalent implementation is allowed only if it provides the same guarantees.

The pump is a transport mechanism, not a new event bus/runtime.

## 7.4 Pump rules

Exactly one provider-event pump may exist per active stream.

It must:

```text
iterate the provider adapter
place normalized/raw adapter events into a private bounded/unbounded per-call queue
report provider iterator completion
report provider exceptions safely
observe/signal the existing cancellation token where possible
never become a global registry or background service
```

The public gateway iterator owns:

```text
deadline
public event normalization
terminal semantics
dropping late provider events
```

## 7.5 Timeout behavior

When remaining deadline expires:

1. mark/cancel the same call cancellation token where the contract allows;
2. emit exactly one normalized `ERROR(PROVIDER_TIMEOUT)` terminal event;
3. stop public iteration immediately;
4. never emit queued/provider events arriving after the deadline;
5. never wait indefinitely for pump termination.

Adapter cooperation remains required for complete provider-resource cleanup, but public Model Gateway latency must remain bounded.

## 7.6 Worker cleanup

The implementation must not make Python process shutdown depend on a permanently blocked provider iterator.

Use a lifecycle appropriate for a per-call transport worker, for example a daemon thread or equivalent non-blocking cleanup mechanism.

Do not introduce:

```text
global thread pool runtime
global stream executor
new event bus
persistent worker registry
```

## 7.7 Cancellation interaction

External cancellation and timeout both terminate public iteration.

They must remain distinguishable:

```text
external/user cancellation -> CANCELLED
deadline expiration -> ERROR(PROVIDER_TIMEOUT)
```

No content may follow either terminal state.

## 7.8 Required tests

RED tests must include:

```text
STARTED
provider blocks longer than timeout
provider later yields "LATE"
=> "LATE" never public
=> PROVIDER_TIMEOUT terminal exactly once
=> elapsed public wait bounded

provider never yields again
=> public iterator returns timeout within bounded tolerance
=> test process does not hang

provider raises in pump
=> safe normalized provider/stream failure

cancellation while pump blocked
=> public CANCELLED terminates without late content
```

## 7.9 Acceptance integration

Add at least the late-content adversarial case to `AT-DP-121`.

# 8. MAJOR-04 design — legacy provider wrapper must reject unrepresentable features

## 8.1 Problem

`LLMProviderModelAdapter` correctly rejects:

```text
multimodal
explicit reasoning effort
streaming
```

but silently discards:

```text
tools
structured_output
```

because legacy `LLMRequest` cannot transport them.

## 8.2 Required behavior

A provider adapter must satisfy exactly one of:

```text
translate canonical feature faithfully
OR
fail closed before provider I/O
```

Silent dropping is forbidden.

## 8.3 Legacy adapter rule

Until the legacy `LLMProvider` contract gains a truthful transport for these features:

```text
request.tools != ()
=> CAPABILITY_UNSUPPORTED before provider.generate()

request.structured_output is not None
=> CAPABILITY_UNSUPPORTED before provider.generate()
```

Use the existing canonical gateway error surface.

No new error taxonomy is required.

## 8.4 Provider call count

For either unsupported feature:

```text
wrapped provider generate call count = 0
```

## 8.5 Combined request

If both are requested, behavior must remain deterministic and safe.

The exact first reported unsupported capability may follow stable validation order, but neither may be dropped.

## 8.6 Streaming wrapper

The legacy wrapper already rejects streaming.

No fake tool/structured streaming support should be added.

## 8.7 Required tests

RED:

```text
legacy adapter + tools
=> CAPABILITY_UNSUPPORTED
=> provider.generate calls = 0

legacy adapter + structured output
=> CAPABILITY_UNSUPPORTED
=> provider.generate calls = 0

legacy adapter + tools + structured output
=> fail closed
=> provider.generate calls = 0

plain text legacy request
=> prior behavior unchanged
```

## 8.8 Acceptance/regression placement

This may be a focused adapter regression rather than a separate large acceptance scenario, provided `AT-DP-121` still proves the gateway never silently drops canonical required features.

# 9. MAJOR-05 design — persist Phase 11.21 capabilities in the existing Phase 11.34 state owner

## 9.1 Problem

Canonical `ModelCapabilities` now includes:

```text
reasoning_efforts
document_media_types
streaming
```

but Phase 11.34 `provider_state.py` serializes only the older capability fields.

A state round trip loses the new truth.

## 9.2 Ownership ruling

The fix MUST stay inside the existing canonical Phase 11.34 persistence owner:

```text
kernel/llm/provider_state.py
```

No new:

```text
model capability store
gateway state store
migration registry
parallel provider-state repository
```

is allowed.

## 9.3 Persisted schema ruling

The repository already documents this persistence policy:

> when the persisted aggregate shape changes, increment `SCHEMA_VERSION`; the prior version is rejected fail-closed rather than reconstructed with assumed defaults.

Remediation V1 follows the same rule.

Change:

```text
SCHEMA_VERSION="2"
```

to:

```text
SCHEMA_VERSION="3"
```

because the persisted model-capabilities shape changes.

## 9.4 Version 3 model capability shape

Persist all prior boolean fields unchanged plus:

```text
reasoning_efforts: list[str]
document_media_types: list[str]
streaming: bool
```

`reasoning_efforts` values are canonical `ReasoningEffort.value` strings.

`document_media_types` preserves the canonical normalized tuple/list order.

`streaming` is a strict bool.

## 9.5 Strict deserialization

Version 3 deserialization must:

```text
require all version-3 capability fields
reject unknown capability fields
reject missing capability fields
reject invalid reasoning effort values
reject duplicate reasoning efforts
reject malformed media types
reject non-bool streaming
```

Reuse `ModelCapabilities` validation rather than duplicate its semantic normalization.

## 9.6 Version 2 behavior

Version 2 persisted documents are no longer accepted by this build.

Required:

```text
schema_version="2" -> ProviderStateSchemaError
```

Do not silently load v2 and assume:

```text
reasoning_efforts=()
document_media_types=()
streaming=False
```

because that recreates the audited loss.

No migration path is introduced in Remediation V1.

## 9.7 Capture / repository / coordinator

The existing:

```text
capture
serialize
repository save/load
coordinator restore
```

path must carry version 3 without creating any new state authority.

## 9.8 Required tests

RED tests:

```text

    reasoning_efforts=(HIGH, EXTRA_HIGH),
    document_media_types=("application/pdf", "text/plain"),
    streaming=True

```

```text
-> ModelCatalog
```

```text
non-bool streaming rejected
```
