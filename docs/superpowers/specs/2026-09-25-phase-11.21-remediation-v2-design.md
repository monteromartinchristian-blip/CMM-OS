## 3. Exact residual defect

The current AUTO path obtains canonical ordered candidates and then performs a global candidate-set egress precheck before iterating them.

Conceptually:

```text
matches = find_matching_models(...)
require_egress_authority(matches, request)
for candidate in matches:
    ...
```

If:

```text
matches = [remote candidate, local candidate]
request.privacy = None
```

the global egress precheck fails before the local candidate can be considered.

Observed independently in Re-audit V2:

```text
error=PRIVACY_DENIED
remote_adapter_calls=0
local_adapter_calls=0
```

This is inconsistent with the gateway's own local execution semantics:

```text
local provider + privacy=None
=> privacy not required
```

and with Remediation V1's per-candidate hard-gate design.

---

## 4. Canonical semantic ruling

Privacy/egress authority in AUTO is evaluated **per candidate**, not per candidate set.

Required AUTO flow:

```text
ordered_candidates = find_matching_models(...)

for candidate in ordered_candidates:
    validate provider/model availability
    validate reasoning/capabilities/modalities
    resolve adapter
    evaluate privacy for this candidate's provider

    if candidate-local hard gate fails:
        continue

    return first executable candidate

fail closed after exhaustion
```

The canonical ordering returned by `find_matching_models(...)` remains untouched.

---

## 5. Explicit model semantics remain stricter

This remediation applies only to AUTO candidate continuation.

For explicit remote model selection:

```text
EXPLICIT remote + privacy=None
=> PRIVACY_DENIED before provider I/O

EXPLICIT remote + no privacy gate
=> PRIVACY_DENIED before provider I/O
```

No fallback/substitution is allowed unless separately authorized by the existing contract.

This remediation must not weaken explicit-model privacy guarantees.

---

## 6. AUTO + local provider semantics

A local candidate must not require remote-egress privacy authority merely because another remote candidate appears earlier in the AUTO set.

Required:

```text
AUTO:
remote first
local second
privacy=None

remote candidate:
not executable because remote egress lacks canonical privacy authority

local candidate:
privacy not required
execute local candidate
```

Result:

```text
remote_adapter_calls=0
local_adapter_calls=1
selected_model=local
```

---

## 7. AUTO + missing privacy gate semantics

If the gateway has no privacy gate/adapter authority available:

```text
AUTO mixed remote/local
```

must still allow a local candidate that requires no remote egress.

Required:

```text
remote candidate -> candidate-local fail
local candidate -> executable
```

But:

```text
AUTO only remote candidates + no privacy gate
=> fail closed
=> zero remote provider calls
```

---

## 8. Candidate-local vs request-global failures

Candidate-local failures that AUTO may skip include:

```text
provider unavailable
model unavailable
adapter unavailable
reasoning effort unsupported
modality unsupported
required capability unsupported
remote privacy/egress denied for that candidate
```

Request-global terminal failures remain terminal:

```text
invalid canonical request
invalid input part
invalid tool contract
invalid structured-output contract
already-cancelled request
internal invariant violation
```

Do not turn arbitrary exceptions into candidate-local continuation.

---

## 9. Required implementation change

Remove or narrow the global AUTO candidate-set egress precheck.

The implementation must not call a helper that denies the entire AUTO request solely because:

```text
any candidate is remote
and privacy metadata is absent
```

Allowed implementation shapes:

```text
delete global precheck and rely on per-candidate privacy gate
```

or:

```text
narrow global precheck so it applies only when every candidate requires remote egress
```

Preferred design: keep the logic simple and evaluate privacy only where provider-specific execution is being considered.

No new abstraction is required unless it clearly reduces duplication.

---

## 10. AUTO exhaustion semantics

After all candidates fail:

```text
fail closed
```

The final safe error may be:

```text
PRIVACY_DENIED
CAPABILITY_UNSUPPORTED
PROVIDER_NOT_AVAILABLE
MODEL_UNAVAILABLE
```

depending on the most relevant existing exhaustion policy.

Do not invent a new routing-policy error.

Do not expose raw provider exceptions.
