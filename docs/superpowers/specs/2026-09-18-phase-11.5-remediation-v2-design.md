# 6. MAJOR_R1_01 — Truthful Domain Projection Capability

## 6.1 Finding

Current production truth table freezes:

```text
domain_projection.status=AVAILABLE
domain_projection.effective=authorized_projection_when_supplied_by_canonical_integrator
```

even when `ConversationService` is constructed with:

```text
domain_projections=None
```

At the same time the service correctly returns no Domain visibility.

This violates the Remediation V1 requirement:

```text
no canonical authorized projection source
→ domain_projection = UNAVAILABLE
```

The defect is capability truthfulness, not Domain authorization leakage.

---

## 6.2 Architectural Principle

Capability truth must be derived from the **actual service composition**.

The conversational resolver must not inspect:

- a visible Domain reference;
- an application trace;
- Domain packages;
- session metadata;
- request metadata;
- a Bot association;
- an Orchestrator result;
- an import state;
- a registry;
- mutable runtime discovery.

The only relevant truth is:

```text
ConversationService has an AuthorizedDomainProjectionSource
or
ConversationService does not have one
```

This is a composition fact, not user input and not inferred authority.

---

## 6.3 Chosen Design

`ConversationCapabilityResolver` remains the single capability resolver.

It gains a narrow, explicit composition-truth input on resolution:

```python
resolve(
    requested: Iterable[str] = (),
    *,
    domain_projection_available: bool = False,
) -> tuple[ConversationCapabilityState, ...]
```

The default is deliberately fail closed:

```text
domain_projection_available=False
```

This means a resolver used without service-composition evidence never claims Domain projection is available.

`ConversationService` supplies the composition truth:

```python
domain_projection_available = self._domain_projections is not None
```

and passes that truth into the existing resolver when projecting the public response.

No source object is passed into the resolver.

No Domain method is called by the resolver.

No new registry or discovery layer is introduced.

---

## 6.4 Why Resolution-Time Composition Truth

The `AuthorizedDomainProjectionSource` belongs to `ConversationService`, not to the capability resolver.

Injecting an independent `domain_projection_available=True` flag into the resolver constructor would allow the resolver and service composition to disagree:

```text
resolver says available
service has no source
```

That is exactly the class of divergence Remediation V2 must eliminate.

Therefore the service remains the composition authority and supplies the boolean at resolution time.

---

## 6.5 Fixed Domain Capability States

When no source is composed:

```text
capability=domain_projection
status=UNAVAILABLE
effective=None
reason=NO_AUTHORIZED_DOMAIN_PROJECTION_SOURCE
```

A stable public reason constant must be introduced:

```text
REASON_NO_AUTHORIZED_DOMAIN_PROJECTION_SOURCE
    = "NO_AUTHORIZED_DOMAIN_PROJECTION_SOURCE"
```

When a valid source is composed:

```text
capability=domain_projection
status=AVAILABLE
effective=<existing authorized projection effective mode>
reason=None
```

The remediation should preserve the existing effective-mode string unless implementation tests prove that it is itself a public factual contradiction requiring a narrow correction.

The preferred minimal path is to preserve:

```text
authorized_projection_when_supplied_by_canonical_integrator
```

for compatibility.

No new status enum is required.

No new capability ID is required.

---

## 6.6 Requested Flag Semantics

The caller may request:

```text
domain_projection
```

but request intent never changes availability.

Without a source:

```text
requested=True
status=UNAVAILABLE
effective=None
reason=NO_AUTHORIZED_DOMAIN_PROJECTION_SOURCE
```

With a source:

```text
requested=True
status=AVAILABLE
effective=<authorized mode>
reason=None
```

The same truth applies when `requested=False`.

---

## 6.7 Per-Service, Not Per-Turn, Availability

A composed source may validly return:

```text
None
```

for a particular turn.

That does **not** make the capability unavailable.

Capability availability means:

```text
the canonical authorized projection mechanism is composed and callable
```

not:

```text
this specific turn happened to produce visible Domain data
```

Therefore:

```text
source composed + turn projection None
→ domain_projection remains AVAILABLE
→ Domain visibility for that turn remains empty
```

Only absence of the canonical source makes the capability `UNAVAILABLE`.

---

## 6.8 Fail-Closed Type Semantics

`domain_projection_available` must be a real boolean composition fact.

Values such as:

```text
1
0
"true"
"false"
None
object()
```

must not be silently coerced.

The implementation plan must define the exact fail-closed exception convention consistent with existing resolver call-site type validation.

The simplest acceptable production rule is:

```python
type(domain_projection_available) is bool
```

with a call-site type failure otherwise.

This is not public HTTP input.

---

## 6.9 Frozen Baseline Table

`domain_projection` must no longer be an unconditional AVAILABLE row inside the static baseline table.

Two acceptable implementations are:

1. remove `domain_projection` from the unconditional `_BASELINE_STATES` map and resolve it in a dedicated `_domain_projection_state(...)` method; or
2. retain a static fail-closed default row (`UNAVAILABLE`) and override it only through the explicit service-composition boolean.

Preferred:

```text
dedicated _domain_projection_state(...)
```

because it mirrors the existing dynamic cancellation capability and makes the composition dependency explicit.

Do not make `_BASELINE_STATES` mutable.

---

## 6.10 Service Wiring

Every path that creates an `AssistantResponse` through the service must use the same truth:

```text
self._domain_projections is not None
```

There must be no path where:

```text
Domain view source absent
but capability resolver receives True
```

and no path where:

```text
Domain view source present
but service silently omits composition truth
```

Submit, edit and regenerate must converge on the same response-projection helper.

# 7. MINOR_R1_02 — Strict Supporting-Domain Provenance Binding

## 7.1 Finding

Current helper:

```python
_public_sequence(value)
```

normalizes malformed application evidence:

```text
None → ()
["domain:foo", 7] → ("domain:foo",)
```

The Domain binding verifier is an adversarial trust boundary.

It must validate provenance, not repair it.

---

## 7.2 Required Strict Grammar

The application response must explicitly contain the key:

```text
supporting_domains
```

Missing key:

```text
FAIL CLOSED
```

`None`:

```text
FAIL CLOSED
```

Scalar string:

```text
FAIL CLOSED
```

Bytes-like values:

```text
FAIL CLOSED
```

Non-sequence values:

```text
FAIL CLOSED
```

Sequence containing any non-string element:

```text
FAIL CLOSED
```

Valid empty sequence:

```text
()
```

Valid all-string sequence:

```text
exact tuple preserving order and membership
```

No elements may be dropped.

No values may be stringified.

No absent value may become an empty sequence.

---

## 7.3 Chosen Binding Shape

The binding verifier must distinguish:

```text
key missing
```

from:

```text
key present with invalid value
```

It must not use:

```python
data.get("supporting_domains")
```

as the sole provenance check because that conflates missing and `None`.

Preferred shape:

```python
if "supporting_domains" not in data:
    raise ConversationProjectionBindingError()

supporting_domains = _strict_public_string_sequence(data["supporting_domains"])
if supporting_domains is None:
    raise ConversationProjectionBindingError()
```

The existing helper may be renamed if clarity improves.

No new public contract type is required.

---

## 7.4 Exact Equality Remains Mandatory

After strict grammar validation:

```text
tuple(projection.conversational.supporting_domains)
==
validated application supporting_domains
```

must remain exact.

No sorting.

No set conversion.

No deduplication.

No normalization of identifiers.

No Domain membership inference.

---

## 7.5 Other Binding Checks Must Remain

Remediation V2 must preserve the existing checks for:

```text
DomainInterfaceProjection exact type
current request ID
ApplicationResponse request ID
current canonical session
ApplicationResponse session
primary_domain equality
canonical resolution_reference_id
conversational view existence
```

The remediation does not weaken any existing MAJOR-02 protections.

---

## 7.6 Required Tests for MINOR_R1_02

Direct verifier RED→GREEN tests must cover:

```text
supporting_domains key missing
supporting_domains=None
supporting_domains="domain:foo"
supporting_domains=b"..."
supporting_domains=object()
supporting_domains=["domain:foo", 7]
supporting_domains=[7]
supporting_domains={{}}
```

All fail closed.

Valid cases:

```text
supporting_domains=[]
supporting_domains=()
supporting_domains=["domain:foo"]
supporting_domains=("domain:foo", "domain:bar")
```

must preserve exact order and equality.

At least one service-level adversarial test must demonstrate malformed application supporting-domain evidence cannot become persisted Domain visibility.
