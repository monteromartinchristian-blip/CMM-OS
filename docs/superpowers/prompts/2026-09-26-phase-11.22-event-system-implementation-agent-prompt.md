## 18. Subscriber retry semantics

Retries are per subscriber.

Required behavior:

```text

subscriber B fails
→ A remains successful
→ only B retries
```

Retry invariants:

- finite retry count;
- same event ID;
- no new event record per attempt;
- no duplicate normal delivery to successful subscribers;
- no new event merely because a retry occurs;
- retry exhaustion produces exactly one dead-letter record.

Do not build generalized recovery.

Do not add circuit breakers.

Do not implement Phase 11.24.

Preserve backward-compatible direct bus behavior.

If legacy direct bus use currently has one attempt, retain that unless an additive configuration explicitly enables retries.
