## 4. Exact finding

The existing sensitive private filename family already includes:

```text
id_rsa
id_dsa
id_ecdsa
id_ed25519
known_hosts
```

through an existing signature equivalent to:

```python
re.compile(
    r"(?:^|[\\/])(?:id_rsa|id_dsa|id_ecdsa|id_ed25519|known_hosts)(?:$|\\.)"
)
```

Independent V12 audit found two structural Windows-semantic blind spots:

1. case variation;
2. NTFS named-stream suffixes using `:`.

Exact reproduced bypasses include:

```text
ID_RSA
KNOWN_HOSTS
Id_Ed25519.pub
provider/ID_RSA
cmm/KNOWN_HOSTS

id_rsa:stream
known_hosts:ads
id_ed25519:foo
id_ecdsa:data
provider/id_rsa:stream
cmm/known_hosts:ads
```

Canonical example:

```text
id_rsa:stream
```

was independently shown to pass `is_private_filesystem_reference`, `validate_platform_identifier`, normal `EventSystem.publish(...)`, manual/prebuilt `publish_event(...)`, both official repositories, and all 13 shared identifier-bearing channels. The file-backed store reopened with the exact unsafe value persisted.

## 5. Required canonical fix

Stay inside the existing sensitive-private-filename signature in the canonical `event_payload_safety` authority.

Required semantic behavior:

- already-sensitive basenames are case-insensitive for safety classification;
- `:` is a valid suffix boundary for those already-sensitive basenames;
- existing `.` suffix behavior remains;
- behavior is structural and independent of any stream name.

A likely conceptual shape is:

```text
(?:^|[\\/])
(?:id_rsa|id_dsa|id_ecdsa|id_ed25519|known_hosts)
(?:$|[.:])
```

with case-insensitive matching, but inspect the actual implementation and retained tests before coding.

Do not add literals such as `ID_RSA`, `KNOWN_HOSTS`, `stream`, `ads`, `foo`, `data`.

Do not reject every colon-bearing identifier.

Do not reject every generic `filename:stream` form.

The invariant is narrow: an already-sensitive private basename must not become public-safe by case variation or by attaching a named-stream suffix.

No filesystem I/O. No `Path.resolve()`. No grammar widening. No rewriting of accepted values.
