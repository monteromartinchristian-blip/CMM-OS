# 7. MAJOR-001 — Make event fingerprint genuinely content-bound

## Audit finding

The canonical `event_fingerprint()` omits material persisted fields.

Audit V1 independently reproduced two materially different events with the same event ID and payload but different:

- `correlation_id`;
- `causation_id`;
- `sensitivity`;
- `metadata`;

and obtained the same fingerprint.

This violates content-bound deduplication and weakens stored-record tamper detection.

## Primary area

Inspect:

```text
cmm/agent_runtime/runtime_event_factory.py
cmm/agent_runtime/runtime_event_repository.py
```

Also inspect any canonical serialization tests before changing behavior.

## RED tests

Add adversarial tests proving the fingerprint changes when each material canonical persisted field changes independently.

At minimum cover every persisted event-header field and every persisted payload field, including where present:

- event ID;
- event type;
- schema version;
- occurred time;
- emitted time;
- agent ID;
- agent run ID;
- goal ID;
- workflow ID;
- task ID;
- iteration ID;
- correlation ID;
- causation ID;
- actor ID;
- source;
- producer;
- aggregate ID;
- sensitivity;
- permissions;
- metadata;
- payload data;
- payload raw if the general Phase 9 serialization contract persists it.

Do not assume this list is exact: derive the definitive list from canonical `to_dict()` serialization.

## Implementation requirement

The fingerprint must cover the **complete canonical persisted event content**.

Preferred principle:

```text
fingerprint = hash(canonical deterministic serialization of the complete event)
```

Do not maintain a second manually drifting list of fingerprint fields if the canonical serializer can be safely reused.

Avoid recursion if the persisted repository wrapper contains a fingerprint field outside the event serialization.

The fingerprint must remain deterministic.

## Identity-conflict regression

Create:

- event A;
- event B with the same event ID;
- change only one material canonical field.

Required:

```text
fingerprint(A) != fingerprint(B)
```

Saving B after A must produce the canonical identity-conflict failure.

## Tamper regression

Write a valid durable event record.

Mutate one material stored field such as:

```text
correlation_id
```

without updating the stored fingerprint.

Reopen/read.

Required:

```text
canonical corruption failure
```

Repeat for at least one security-sensitive field such as sensitivity or metadata.

## Compatibility

Existing unchanged-event fingerprints must remain deterministic within the new implementation.

No requirement exists to preserve old V1 fingerprint values across the remediation because the fingerprint algorithm was incorrect, but inspect whether stored fixtures depend on exact values.

Do not silently make old malformed V1 persistent data look valid.

# 8. MAJOR-002 — Close `EventSystem.publish_event()` safety/registry bypass

## Audit finding

`EventSystem.publish()` uses the bounded platform validator.

Public `publish_event()` currently allows a manually constructed `AgentRuntimeEvent` to reach persistence without enforcing the same platform boundary.

Audit V1 reproduced:

```text
goal.created
payload={"prompt": "TOP SECRET"}
→ persisted
```

and:

```text
totally.unknown.event
payload={"prompt": "TOP SECRET", "opaque": object()}
→ accepted by in-memory publication path
```

The durable repository also accepted manually constructed prompt-bearing canonical events.

## Primary area

Inspect:

```text
cmm/events/event_system.py
cmm/events/payload_policy.py
cmm/agent_runtime/runtime_event_factory.py
cmm/agent_runtime/runtime_event_registry.py
```

## RED tests — direct public boundary

Call `EventSystem.publish_event()` directly with manually constructed canonical event objects.

Required failures before persistence for:

1. unknown event type;
2. `prompt`;
3. `system_prompt`;
4. `developer_prompt`;
5. `chain_of_thought`;
6. `hidden_reasoning`;
7. credential/API-key/token/password-bearing fields;
8. raw provider request/response;
9. opaque object;
10. binary payload;
11. unsafe `payload.raw`.

Verify:

```text
repository.count() == 0
subscriber not invoked
DLQ unchanged
```

## Implementation requirement

`publish_event()` must itself be a canonical platform publication validation boundary.

Before persistence it must:

1. verify canonical registry membership;
2. validate platform payload safety;
3. reject unsafe raw payload content;
4. normalize the canonical event;
5. preserve the supplied event ID;
6. preserve legitimate correlation/causation and other canonical header facts;
7. then enter the existing persist-before-deliver flow.

Do not make safety dependent on the caller choosing `publish()` instead of `publish_event()`.

## Avoid a new authority

Do not create another validator hierarchy.

Reuse the existing Phase 11.22 bounded payload policy and existing registry.

If a private helper is useful, it must be a helper inside the existing facade, not a new platform event authority.

## Durable repository scope

The platform safety boundary belongs in the platform publication path.

Do not turn the generic Phase 9 repository into a Phase 11.22 platform-policy authority unless an existing canonical contract explicitly requires that.

However durable deserialization/integrity checks remain fail-closed.

# 9. MAJOR-003 — Make dead-letter replay subscriber-targeted

## Audit finding

A DLQ entry records the failed `subscription_id`, but `replay_dead_letter()` replays the event globally to every replay-enabled subscriber.

Audit V1 reproduced:

```text
subscriber A:
  normal delivery fails
  accept_replay=False

subscriber B:
  normal delivery succeeds
  accept_replay=True
```

After DLQ replay:

```text
A was not retried
B received replay
A's DLQ entry was removed
```

This falsely resolves another subscriber's failed delivery.

## Primary area

Inspect:

```text
cmm/events/event_system.py
cmm/agent_runtime/runtime_event_bus.py
cmm/agent_runtime/runtime_event_replay.py
cmm/agent_runtime/runtime_event_dead_letter.py
```

## RED regression

Create exactly the audit scenario:

```text
A = failing, replay-disabled
B = successful, replay-enabled
```

Required:

```text
replay_dead_letter(A_entry)
→ must not deliver to B as a substitute for A
→ must not remove A's DLQ entry
```

Add second scenario:

```text
A = originally failed, replay-enabled, now succeeds
B = unrelated replay-enabled
```

Required:

```text
only A is targeted
A succeeds
A's DLQ entry is removed
B is not invoked by this targeted DLQ replay
```

Add failure scenario:

```text
A remains failing
→ A's DLQ entry remains
```

## Implementation requirement

Use the recorded:

```text
subscription_id
```

as the target.

Extend the existing canonical bus/replayer **additively** if necessary with a targeted replay-delivery capability.

Do not create a second replay engine.

Do not broadcast DLQ replay.

Do not clear the dead letter merely because some other replay subscriber accepted the event.

## Replay policy

Preserve the audit remediation rule:

```text
target subscriber must itself be replay-authorized
```

If the failed subscriber has `accept_replay=False`:

```text
DLQ entry remains unresolved
```

Do not bypass replay policy through the DLQ API.
