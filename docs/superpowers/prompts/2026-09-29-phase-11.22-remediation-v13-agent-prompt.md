## 4. MAJOR-V13-001 — Win32 trailing-period path-component equivalents

### 4.1 Exact independently reproduced bypass

The canonical classifier already rejects sensitive path families such as:

```text
.ssh
.aws
.gnupg
.kube
.docker
.azure
Users
home
Documents and Settings
```

but does not account for Win32 trailing-period component normalization.

Independent V13 audit demonstrated opposite verdicts for Windows-equivalent spellings:

```text
provider/.ssh/config       REJECT
provider/.ssh./config      ACCEPT + persist

provider/Users/alice/config    REJECT
provider/Users./alice/config   ACCEPT + persist
```

Fresh accepted unsafe family included:

```text
provider/.ssh./config
provider/.SSH./config
provider/.aws./config
provider/.gnupg./trustdb.gpg
provider/.kube./config
provider/.docker./config.json
provider/.azure./profile
provider/Users./alice/config
provider/users./alice/config
provider/home./alice/config
cmm/.ssh./config
cmm/Users./alice/config
provider/.ssh../config
provider/Users../alice/config
```

The canonical value:

```text
provider/.ssh./config
```

was independently accepted and persisted through:

- all 13 shared identifier-bearing channels;
- official in-memory repository;
- official file-backed repository;
- manual/prebuilt `EventSystem.publish_event(...)`.

The file-backed store was reopened and retained the exact unsafe spelling.

### 4.2 Root cause

The existing `_analyze_lexical_path()` analysis currently performs, in essence:

- backslash-to-slash normalization for analysis;
- repeated separator collapse;
- exact `.` segment elision;
- `..` traversal detection before elision;
- no filesystem I/O;
- no `Path.resolve()`.

It does **not** normalize ordinary Win32 trailing ASCII periods from otherwise named path components.

Therefore:

```text
.ssh.
```

remains `.ssh.` in the analysis form instead of the Windows-equivalent `.ssh`.

The sensitive-directory regex does not match, and the outer public slash root then makes the reference appear safe.
