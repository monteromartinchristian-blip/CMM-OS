# 7. MAJOR-V6-001 — Numeric lifecycle facts must be truly bounded and repository-independent

## Audit finding

The V5 semantic classes correctly distinguish numeric lifecycle fields from arbitrary prose, but the numeric validator still accepts any finite Python number.

Independent V6 reproduction:

```text
count = 10 ** 5000
```

through the public Phase 11.22 path:

```text
in-memory repository -> ACCEPTED
file-backed repository -> ValueError during serialization
```

The same safety boundary also accepted values such as:

```text
count=-1
duration_ms=-5
attempts=-1
sequence=-1
duration_ms=1e308
```

where current lifecycle semantics imply bounded non-negative facts.

The frozen design allows:

```text
bounded counts
safe durations
```

not arbitrary finite numbers.

## Required RED tests

Before production changes, reproduce:

```text
count=10**5000
```

through:

```text
InMemoryAgentRuntimeEventRepository
FileAgentRuntimeEventRepository
```

and show current divergence.

Also reproduce, for fields whose current contract is non-negative:

```text
count=-1
attempt=-1
attempts=-1
sequence=-1
duration_ms=-1
retry_after_ms=-1
```

and at least one oversized finite float.

Control legitimate values:

```text
count=0
count=1
attempt=1
duration_ms=0
duration_ms=125
retry_after_ms=1000
```

where current producers support them.

## Required inventory before choosing bounds

Inspect all current legitimate numeric lifecycle fields and producers.

At minimum inventory:

```text
count
attempt
attempts
sequence
duration_ms
retry_after_ms
ratio
```

and any other numeric keys in the actual `PAYLOAD_KEY_CLASSES` / metadata classes.

Do not invent arbitrary bounds without checking current usage.

Choose explicit constants or one small semantic table in the **existing safety authority**.

## Required implementation

Enforce actual bounds before repository interaction.

At minimum:

### Count / attempt / sequence semantics

For fields that semantically represent counts, attempts or sequence values:

```text
type = int
bool excluded
non-negative unless current contract explicitly requires signed values
explicit maximum
```

The maximum must be low enough to prevent serializer/interpreter boundary abuse and high enough for all legitimate current use.

### Duration semantics

For duration/retry fields:

```text
int or float as currently contractually supported
bool excluded
finite
non-negative
explicit maximum
```

Do not allow absurd but finite values such as `1e308`.

### Ratio semantics

If `ratio` is a normalized ratio:

```text
0.0 <= ratio <= 1.0
```

only if that matches current actual usage.

If current usage proves a different range, preserve the real contract and document it.

## Required invariant

```text
NUMERIC_FACTS_REJECT_BEFORE_REPOSITORY_INTERACTION
IN_MEMORY_AND_FILE_REPOSITORY_PARITY=PASS
BOUND_MEANS_ACTUALLY_BOUNDED
```

# 9. MAJOR-V6-003 — Canonical header facts must have one authority; payload must not shadow them

## Audit finding

The V5 semantic payload vocabulary still contains keys equivalent to canonical header facts.

Independent V6 reproduction persisted contradictory values simultaneously:

Canonical header:

```text
event_id=header-event
correlation_id=header-corr
causation_id=header-cause
producer=header-producer
sensitivity=internal
```

Payload:

```text
event_id=payload-event
correlation_id=payload-corr
causation_id=payload-cause
producer=payload-producer
sensitivity=restricted
```

Both persisted.

This violates:

```text
one canonical identity/correlation/sensitivity authority
```

and creates dangerous ambiguity around classification.

## Required inventory

Inspect the payload vocabulary for every key semantically duplicating canonical header facts.

At minimum review:

```text
event_id
event_type
schema_version
occurred_at
correlation_id
causation_id
producer
sensitivity
```

Also inspect any field semantically equivalent under a different spelling.

## Preferred canonical decision

The canonical header remains authoritative.

Preferred remediation:

```text
equivalent canonical header facts are not persisted as platform payload facts
```

If adapters currently accept source dictionaries containing these names, consume/map them into the canonical header during event construction and remove them from the persisted platform payload.

Do not silently maintain two copies.

## Compatibility alternative

If current producer compatibility absolutely requires an equivalent payload key:

```text
payload value must equal canonical header value exactly after normalization
```

and no conflicting duplicate may persist.

But the preferred design remains one authoritative representation.

## Sensitivity rule

No event may persist:

```text
header.sensitivity != payload.sensitivity
```

in any equivalent field.

A stricter source sensitivity must be promoted to the canonical header before persistence, never hidden only in payload.

A lower payload sensitivity must never downgrade the canonical header.

Preserve the already-fixed Domain/Kernel sensitivity fidelity behavior.

## Required RED tests

At minimum:

```text
payload event_id conflicts with header event_id
payload correlation_id conflicts with header
payload causation_id conflicts with header
payload producer conflicts with header
payload sensitivity stricter than header
payload sensitivity lower than header
payload event_type conflicts with header
payload schema_version conflicts with header
payload occurred_at conflicts with canonical occurred_at
```

Control:

```text
source adapter still constructs correct canonical header
Domain/Kernel sensitivity preservation remains green
correlation/causation remain preserved
```

## Required invariant

```text
ONE_CANONICAL_HEADER_FACT_AUTHORITY=PASS
NO_CONFLICTING_HEADER_EQUIVALENT_PAYLOAD_FACTS=PASS
```
