# Phase 10.49 — Domain Knowledge Packages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add declarative Domain-owned specialization, deterministic multi-domain composition, and fail-closed validation over the canonical Phase 8 `KnowledgePackage`, with twelve current first-party schemas and no parallel knowledge infrastructure.

**Architecture:** `DomainDefinition` gains an optional `DomainKnowledgePackageSchema`; schemas serialize through the existing Domain Pack path, compose into one immutable effective schema, and validate packages produced only by the canonical Phase 8 `KnowledgePackageBuilder`. The existing `DefaultDomainCognitiveIntegrator` receives an optional effective schema in its request and applies the pure validator after canonical package construction, while every existing call without a schema remains backward-compatible.

**Tech Stack:** Python, frozen/slotted dataclasses, enums, `MappingProxyType`, canonical `cmm.cognitive` contracts, canonical Domain Pack serialization, pytest, Ruff 0.16.2 baseline-aware lint/format gates, `compileall`, Git.

**Spec:** `docs/superpowers/specs/2026-09-10-phase-10.49-domain-knowledge-packages-design.md`

## Canonical Interfaces Locked by This Plan

### `DomainKnowledgePackageFieldPolicy`

```python
@dataclass(frozen=True, slots=True)
class DomainKnowledgePackageFieldPolicy:
    field_name: str
    required_non_empty: bool = False
    minimum_items: int | None = None
    allowed_knowledge_kinds: tuple[KnowledgeKind, ...] = ()
    require_provenance: bool = False
    require_temporal_scope: bool = False
    preserve_uncertainty: bool = False
    preserve_contradictions: bool = False
```

Rules:

- `field_name` names one canonical Phase 8 `KnowledgePackage` field.
- `minimum_items` is `None` or integer `>= 0`; booleans are rejected.
- `allowed_knowledge_kinds` is valid only for knowledge-item category fields.
- Duplicate kinds are rejected.
- Unknown serialized keys are rejected.
- A policy can only narrow or require evidence; it cannot grant authority.

### `DomainKnowledgePackageSchema`

```python
@dataclass(frozen=True, slots=True)
class DomainKnowledgePackageSchema:
    id: str
    domain_id: DomainId
    version: str
    base_schema: str = "KnowledgePackage"
    required_sections: tuple[str, ...] = ()
    optional_sections: tuple[str, ...] = ()
    prohibited_sections: tuple[str, ...] = ()
    field_policies: tuple[DomainKnowledgePackageFieldPolicy, ...] = ()
    minimum_sensitivity: SensitivityLevel = SensitivityLevel.PUBLIC
    validator_refs: tuple[str, ...] = ()
    metadata: Mapping[str, Any] = field(default_factory=dict)
```

Rules:

- `base_schema` is exactly `"KnowledgePackage"`.
- Section identifiers are from a finite canonical package field vocabulary.
- No duplicate section identifiers.
- `required ∩ optional = ∅`.
- `required ∩ prohibited = ∅`.
- `optional ∩ prohibited = ∅`.
- At most one field policy per field.
- A field policy cannot require non-empty content for a prohibited section.
- `minimum_sensitivity` reuses `cmm.cognitive.enums.SensitivityLevel`.
- `validator_refs` are unique non-blank opaque identifiers.
- `metadata` is deeply frozen using existing Domain conventions.
- `to_dict()` / `from_dict()` are strict and deterministic.

### `EffectiveDomainKnowledgePackageSchema`

```python
@dataclass(frozen=True, slots=True)
class EffectiveDomainKnowledgePackageSchema:
    source_schema_ids: tuple[str, ...]
    domain_ids: tuple[DomainId, ...]
    required_sections: tuple[str, ...]
    optional_sections: tuple[str, ...]
    prohibited_sections: tuple[str, ...]
    field_policies: tuple[DomainKnowledgePackageFieldPolicy, ...]
    minimum_sensitivity: SensitivityLevel
    validator_refs: tuple[str, ...]
```

Rules:

- This is effective policy evidence, not a package model.
- `source_schema_ids` and `domain_ids` sort deterministically.
- At least one source schema is required.
- It contains no knowledge payload or mutable user state.

### Composition helper

```python
def compose_domain_knowledge_package_schemas(
    schemas: Iterable[DomainKnowledgePackageSchema],
) -> EffectiveDomainKnowledgePackageSchema:
    ...
```

Composition is deterministic and order-independent:

- reject empty input;
- sort by `(str(domain_id), version, id)`;
- union required and prohibited sections;
- optional = deterministic union minus required/prohibited;
- required/prohibited collision fails closed;
- field policies compose most-restrictively:
  - `required_non_empty`: OR;
  - `minimum_items`: maximum;
  - configured `allowed_knowledge_kinds`: intersection;
  - empty configured intersection: fail closed;
  - `require_provenance`: OR;
  - `require_temporal_scope`: OR;
  - `preserve_uncertainty`: OR;
  - `preserve_contradictions`: OR;
- sensitivity uses explicit rank:
  `PUBLIC < INTERNAL < PERSONAL < SENSITIVE < HIGHLY_SENSITIVE < RESTRICTED`;
- validator refs are deterministic union.

### Validation helper

```python
def validate_domain_knowledge_package(
    package: KnowledgePackage,
    schema: DomainKnowledgePackageSchema | EffectiveDomainKnowledgePackageSchema,
) -> KnowledgePackage:
    ...
```

On success:

```python
validated is package
```

On failure: raise `DomainKnowledgePackageValidationError`.

Validation:

- only accepts canonical `KnowledgePackage`;
- prohibited sections must remain empty/default;
- applies `required_non_empty` / `minimum_items`;
- validates knowledge kinds;
- validates canonical provenance and temporal evidence;
- preserves uncertainty and contradictions without inventing or resolving them;
- derives privacy/sensitivity via canonical Phase 8 privacy helpers;
- never mutates package;
- never resolves or executes validator refs.

### Cognitive integration seam

Append to `DomainCognitiveIntegrationRequest`:

```python

    DomainKnowledgePackageSchema
    | EffectiveDomainKnowledgePackageSchema
    | None
) = None
```

The existing integration sequence becomes:

```text

→ canonical KnowledgePackageBuilder.build(...)
→ optional Phase 10.49 validation
→ canonical CognitiveValidator
→ existing reasoning/rules/presentation/trace
```

`KnowledgePackageBuilder` remains untouched.
