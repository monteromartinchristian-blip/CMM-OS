# Phase 11.34 Provider Registry Remediation V6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close exactly `MAJOR-V6-01` by making `ModelRouteCatalog.restore_all()` preserve historical registration markers only for the same route-to-connection relationship while forcing every fresh or rebound relationship through current canonical connection authority.

**Architecture:** Keep the existing single `ModelRouteCatalog` and its private `_RouteBinding` registration marker. `restore_all()` classifies each incoming route as either an exact relationship rollback (`same route_id + same connection_id`) or a fresh/rebound relationship; rollback preserves the existing marker, while fresh/rebound relations reuse `_current_connection_registration()`. The method remains atomic by building a temporary mapping and swapping `_routes` only after all input validates.

**Tech Stack:** Python 3.10+, pytest, existing Provider Registry in-memory catalogs/coordinator/repository, Ruff 0.16.2, `compileall`, `git archive`.
