# Phase 10.53 Trusted Authority V3 Redo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one shared runtime-only trusted authority channel to canonical
reasoning so Phase 10.53 can distinguish caller metadata from real permission
and Health authority.

**Architecture:** `ReasoningRuleContext.metadata` remains JSON-safe and
non-authoritative. A new `ReasoningAuthorityContext` is carried separately and
can only enter rule execution through trusted in-process integration. The
Neurodivergence certainty rule uses that channel for authoritative clinical
promotion while ordinary exploratory reasoning remains unchanged.

**Tech Stack:** Python dataclasses, existing Cognitive reasoning contracts,
Domain Cognitive integration, Domain Permission Gate, Health diagnostic rules,
pytest, Ruff.

**Original Spec:**
`docs/superpowers/specs/2026-09-13-phase-10.53-neurodivergence-domain-design.md`

## Global Constraints

- Preserve exploratory/hypothesis-friendly Neurodivergence behavior.
- `ReasoningRuleContext.metadata` can never grant authority.
- Runtime authority is separate from request/caller JSON.
- No cryptographic or hostile-in-process-code threat model is introduced.
- No new store, registry, resolver, loader, runtime, engine, or authority
  subsystem.
- Health remains the owner of definitive diagnostic truth.
- DomainPermissionResolver / DomainPermissionGate / ApprovalService remain the
  owners of permission authority.
- CrossDomainContextTransfer remains necessary context but is never authority
  by itself.
- Existing V1/V2 audit evidence and original Phase 10.53 spec/plan are immutable.
- No Phase 11 behavior.
- No push or merge.
- Preserve the quarantine stash.
- No `git reset`, `git clean`, `git worktree`, rebase, cherry-pick, or stash

# Task 1 — Add the runtime-only `ReasoningAuthorityContext`

**Files:**

- Modify: `cmm/cognitive/reasoning_rule_contracts.py`
- Modify: `cmm/cognitive/__init__.py`
- Test: `tests/cognitive/test_reasoning_rule_contracts.py`
- Test: `tests/cognitive/test_reasoning_rule_serialization.py`

**Interfaces:**

Produces:

```python
@dataclass(frozen=True, slots=True)
class ReasoningAuthorityContext:
    actor_id: str
    session_id: str
    source_domain: str
    target_domain: str
    resource_ids: tuple[str, ...]
    purpose: str
    permission_decision_id: str
    permission_outcome: str
    approval_consumed: bool = False
    authoritative_claim_ids: tuple[str, ...] = ()
```

and extends:

```python
@dataclass(frozen=True, slots=True)
class ReasoningRuleContext:
    ...
    metadata: Mapping[str, Any] = field(default_factory=dict)
    authority_context: ReasoningAuthorityContext | None = None
    contract_version: str = REASONING_RULE_CONTRACT_VERSION
```

The exact field order may follow dataclass compatibility rules, but the public
names above are fixed by this plan.

## Contract semantics

`ReasoningAuthorityContext` must validate:

```text
actor_id                     non-blank
session_id                   non-blank
source_domain                canonical domain id
target_domain                canonical domain id
source_domain != target_domain
resource_ids                 unique non-blank strings, non-empty
purpose                      non-blank
permission_decision_id       non-blank
permission_outcome           exactly "allow" or "approval_consumed"
approval_consumed            strict bool
authoritative_claim_ids      unique non-blank strings
```

Additional invariant:

```text
permission_outcome == "approval_consumed"
    -> approval_consumed is True

permission_outcome == "allow"
    -> approval_consumed is False
```

This is not authentication by itself. Trust comes from the fact that only
trusted in-process code places this object on `ReasoningRuleContext`.

## Serialization boundary

`ReasoningRuleContext.to_dict()` must not serialize `authority_context`.

`ReasoningRuleContext.from_dict()` must not accept a caller-supplied
`authority_context`.

A context round-trip therefore behaves as:

```text
trusted runtime context with authority
-> to_dict()
-> authority omitted
-> from_dict()
-> authority_context is None
```

This is intentional authority stripping.

- [ ] Add invalid cases for blank IDs, invalid domains, duplicate/empty
      resources, unknown permission outcome, and inconsistent approval state.
- [ ] Run only those tests and verify RED because the contract does not exist.

Example target assertion:


## Builder behavior

The builder consumes a live typed `PermissionGateResult`.

It returns `None` unless:

```text
gate_result.allowed is True
gate_result.action == PermissionCapability.DOMAIN_CROSS_ACCESS.value
gate_result.outcome in {"allow", "approval_consumed"}
gate_result.decision_id is non-blank
gate_result.actor_id is non-blank
gate_result.session_id is non-blank
gate_result.domain_id is a canonical source domain
gate_result.metadata has canonical cross-domain request evidence
target_domain exists
resource_ids are non-empty
reason/purpose is non-blank
```

It derives, rather than accepts separately:

```text
actor_id
session_id
source_domain
target_domain
resource_ids
purpose
permission_decision_id
permission_outcome
approval_consumed
```

from the typed gate result and its canonical cross-domain metadata.

The only extra trusted input is:

```text
authoritative_claim_ids
```

These claim IDs are supplied by trusted source-owner code after source-domain
authority evaluation. They do not come from the caller request.

## Integration binding

If `authority_context` is supplied to `integrate()`:

```text
request.actor_id == authority_context.actor_id
request.session_id == authority_context.session_id
authority_context.target_domain == request.profile.primary_domain
authority_context.source_domain is in request.profile.supporting_domains
```

must all hold.

Otherwise raise `DomainCognitiveIntegrationContractError`.

The integrator must never derive `authority_context` from:

```text
request.metadata
request.effective_permissions
caller JSON
```
