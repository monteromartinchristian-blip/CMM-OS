# Phase 10.48 — Domain Quality Metrics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add declarative, domain-owned quality metrics plus deterministic aggregation of already-produced metric evidence, without executing benchmarks, evaluators, models, or providers.

**Architecture:** Phase 10.48 appends `quality_metrics` to the existing canonical `DomainDefinition`, reuses the existing Domain Pack/`ParsedDomainPack` parsing path, and introduces one focused contract module for immutable quality policy/evidence/assessment types plus pure helper functions. `DomainRegistry` remains the only Domain registry; Phase 10.47 benchmark contracts remain unweighted; Phase 11.36 retains all evaluator/model execution, comparison, regression, and ranking authority.

**Tech Stack:** Python dataclasses, `Decimal`, canonical JSON serialization, existing `cmm.domains` contracts/errors/identifiers, pytest, Ruff, compileall, Git.

**Spec:** `docs/superpowers/specs/2026-09-10-phase-10.48-domain-quality-metrics-design.md`
