## 1. Implementation objective

Implement exactly one canonical provider-independent Model Gateway over the already-existing CMM OS model/provider infrastructure.

The implementation shall:

- reuse the closed Phase 11.34 Provider Registry without changing its ownership;
- reuse the existing `ModelCatalog`, model discovery, model selection, model requirements, model fallback and provider adapter surfaces where applicable;
- preserve Phase 11.1–11.5 closed semantics;
- add the missing canonical provider-independent execution boundary;
- make reasoning effort and multimodal image/PDF/document inputs real end-to-end gateway features;
- normalize structured output, tool calls, streaming, cancellation, timeout, usage/cost/latency and provider failures;
- enforce canonical privacy immediately before provider egress;
- remain narrower than Phase 11.35 Routing Policy Engine and Phase 11.50 reusable client interfaces.

This plan converts the frozen design into ordered TDD tasks. No task may widen the design.

## 8. Task 4 — RED: provider adapter protocol

### Goal

Create one narrow provider execution protocol.

### Protocol

Conceptually:

```python
class ModelProviderAdapter(Protocol):
    provider_id: str

    def execute(self, request: ProviderModelRequest) -> ProviderModelResponse:
        ...

    def stream(self, request: ProviderModelRequest, cancellation: ...) -> Iterable[ProviderStreamEvent]:
        ...
```

Exact typing may differ.

### Invariants

- gateway core is provider-name agnostic;
- adapters translate canonical request → provider request;
- adapters translate provider response → normalized provider result;
- providers do not receive policy authority;
- adapter factory/resolution reuses existing provider factory/connection state;
- test adapter is official and in-memory, not an isolated mocking trick.

### Existing providers

Prefer wrapper adaptation around current provider implementations.

Do not fork:

```text
OpenAI provider
OpenAI-compatible provider
Ollama provider
```

unless the current implementation structurally cannot be adapted.

### Tests

- adapter lookup is by canonical provider identity/capability;
- duplicate adapter identity fails;
- unsupported streaming fails explicitly;
- provider exception is normalized without raw exception leakage.

### Commit recommendation

