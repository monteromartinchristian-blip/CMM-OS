## Global Constraints

- Phase 10.52 is closed and its implementation/audit history remains immutable.
- Canonical identity is exactly `domain:neurodivergence`.
- Canonical profile is exactly `NeurodivergenceProfile`.
- Design Point is `DP-053`.
- Connected acceptance is `AT-DP-053`.
- Default sensitivity floor is canonical `SensitivityLevel.SENSITIVE`.
- Default privacy orientation is canonical `PrivacyPolicy.LOCAL_ONLY`.
- Neurodivergence is a sibling of Health and Mental Health, not a child namespace.
- Health remains authoritative for documented clinical diagnosis status, medication, treatment, medical tests, medical contraindications and medical safety.
- Mental Health remains authoritative for imported emotional/therapy context.
- University remains authoritative for imported academic/institutional facts.
- Relationships remains authoritative for imported relationship-specific facts.
- Exploratory model inference is allowed.
- Association and pattern reasoning are allowed.
- Working hypotheses are allowed.
- Balanced differential reasoning is required.
- Negative evidence is proportionate, not mechanically mandatory in every reply.
- Default disclaimer spam is prohibited.
- Model inference must never become confirmed clinical diagnosis without canonical authoritative evidence.
- Screening must never become confirmed diagnosis by itself.
- Self-report must never become confirmed diagnosis by itself.
- An isolated trait must never become stable confirmed diagnostic identity by itself.
- Certainty/status must remain visible and non-promotable.
- `CONFIRMED`, `IN EVALUATION`, `HYPOTHESIS`, and negative/insufficient states must remain semantically distinct.
- Do not create a second global epistemic enum or second knowledge truth.
- If pack-local certainty labels are required, they are derived/non-authoritative and cannot upgrade canonical knowledge.
- Permission to infer does not imply permission to persist.
- Permission to read does not imply permission to transfer.
- A `CrossDomainContextTransfer` is not authority by itself.
- Current `DomainPermissionResolver` + `DomainPermissionGate` authority must gate transfer admission.
- `APPROVAL_REQUIRED` is not authorization.
- Canonical approval must be consumed (`APPROVAL_CONSUMED`) before an approval-gated transfer is admitted.
- Approval/resource/actor/session/purpose bindings must remain exact.
- All sensitive persistence is proposal-first.
- Existing Health knowledge must not be silently migrated or duplicated.
- Operations are declarative and unavailable by default unless canonical implementations are explicitly injected.
- Workflows use the existing Domain Workflow registry and shared Workflow Engine only.
- No provider/model-specific authority may be introduced.
- No Phase 11 behavior is introduced.
- No push or merge.
- Do not use `git stash`, `git stash pop/apply/drop`, `git reset`, `git clean`, `git worktree`, `git rebase`, or `git cherry-pick`.
- Preserve the quarantine stash exactly.
- Every implementation task follows `TEST RED → MINIMAL IMPLEMENTATION → GREEN → CONTROLLED REFACTOR → NEXT BLOCK`.
- A failed focused test or regression must be resolved before starting the next task.
- Before audit, all implementation/docs changes are committed and the worktree is clean.
