# Phase 10.43 — Integration with Validation System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate Domain Intelligence with the canonical Phase 7 Validation System so Domain Pack installation/update, Domain operations, Domain workflows, cross-domain execution, specialized results, and Project Domain code changes carry explicit, deterministic, fail-closed validation obligations without creating parallel validation infrastructure.

**Architecture:** Phase 10.43 adds a thin Domain-owned binding layer over existing Phase 7 `ValidationPolicy` / `ValidationRegistry` / `ValidationPipeline` semantics and reuses the existing Phase 9 `AgentValidationAdapter` for agentic execution. **Tech Stack:** Python, dataclasses/enums only where already consistent with repository style, Phase 7 `cmm.validation`, Phase 9 `cmm.agent_runtime`, Phase 10 Domain Intelligence contracts/registries/loaders/planner-workflow integration, pytest, Ruff, `compileall`, Git.

from collections.abc import Iterable

from cmm.validation import ValidationPolicy

    "domain.dependencies",
    "domain.fragmentation",
    "domain.manifest",
    "domain.permissions",
    "domain.security",
    "domain.tests",

def compose_required_validation_ids(
    *groups: Iterable[str],
) -> tuple[str, ...]:
    values = {item for group in groups for item in group}
    if any(not item or not isinstance(item, str) for item in values):
        raise ValueError("validation ids must be non-empty strings")
    return tuple(sorted(values))
