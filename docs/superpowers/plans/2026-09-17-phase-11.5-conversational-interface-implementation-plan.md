# Phase 11.5 Conversational Interface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement `F11-019 — Canonical Conversational Interface` and `DP-105 — Session-Backed Canonical Conversation Boundary` as a thin, versioned, session-backed conversational boundary over the already-closed Phase 11.3 `ApplicationGateway`, Phase 11.2 Orchestrator, canonical shared-session authority, and Phase 10.45 Domain Interface Integration.

**Architecture:** Conversation continuity remains the canonical `session_id`; conversational history is persisted only inside a namespaced `conversation.v1` extension on `SharedSessionState`, using the existing `SessionStore` revision boundary. `ConversationService` is a coordinator, not a runtime: it submits messages through `ApplicationGateway`, combines only public-safe application results with already-authorized `ConversationalDomainView` values, persists auditable message lineage through the canonical session store, and exposes truthful requested/effective capabilities.

**Tech Stack:** Python 3.14, frozen/slotted dataclasses, existing `cmm.runtime.sessions`, Phase 11.3 `cmm.application`, Phase 11.2 `cmm.orchestration`, Phase 10.45 `cmm.domains.interface_integration*`, FastAPI/Pydantic only in the existing `cmm.api` adapter, pytest, Ruff.

**Spec:** `docs/superpowers/specs/2026-09-17-phase-11.5-conversational-interface-design.md`

**Implementation baseline:** branch `feature/phase-11-stable-integrated-platform`, HEAD `29f7f3a5821540e666fd948c2b11e39229c1c76f`.

## Global Constraints

- Implement exactly `F11-019`, `DP-105`, and `AT-DP-105`; do not widen Phase 11.5.
- `conversation continuity identity == canonical session identity`.
- Do not create a general-purpose `ConversationStore`, `ConversationRepository`, `ConversationRuntime`, `ConversationEngine`, `ConversationRouter`, `ConversationPlanner`, `ConversationApprovalManager`, `ConversationPermissionEngine`, `ConversationMemoryStore`, `ConversationKnowledgeStore`, `ConversationProviderRegistry`, `ConversationAgentRuntime`, `ConversationWorkflowEngine`, or `ActiveRequestRegistry`.
- All persistent conversational state must go through canonical `cmm.runtime.sessions.SessionStore`.
- Reuse `SharedSessionState.extensions`; use the namespaced extension key `conversation.v1`.
- Ordinary message submission must go through Phase 11.3 `ApplicationGateway`.
- The application seam added by this phase is additive only: introduce `ApplicationChannel.CONVERSATION` and map it to existing `OrchestrationChannel.CONVERSATION`; do not change API/CLI defaults or closed Phase 11.3 semantics.
- Do not implement model/provider inference, Model Gateway, Web Search, Browser Use, Computer Use, CMMChat UI, CMM Bots runtime, Communication Profiles, audio/Plaud, global file/artifact storage, import/export, or a cancellation runtime.
- Optional `bot_id` remains opaque conversation metadata and grants no authority.
- Attachment/document support is reference-only. No upload or file store is introduced.
- Current Phase 11.3 SSE is `response_event_stream`, not live provider-token generation.
- Current cancellation remains unavailable unless the canonical application owner reports otherwise.
- No hidden chain-of-thought, raw prompts, private scratchpads, raw exceptions, secrets, filesystem paths, credentials, or unauthorized source content may enter public conversational serialization.
- Message editing and regeneration are append-only lineage operations; originals are preserved.
- Use optimistic session revision semantics for every conversational persistence change.
- Preserve `AT-DP-104`, `AT-DP-103`, `AT-DP-102`, `AT-DP-101`, `AT-DP-134`, and especially `AT-DP-045`.
- No `push`, no `merge`, no `git stash`, no stash mutation, no `git reset`, no `git clean`, and no `git worktree` without explicit user authorization.
- Keep the quarantine stash unchanged.
- Follow the cycle `TEST RED → MINIMAL IMPLEMENTATION → GREEN → CONTROLLED REFACTOR → NEXT BLOCK`.
- Resolve every regression before continuing.

## 3. Frozen Session Extension Shape

The canonical extension key is:

```python
CONVERSATION_EXTENSION_KEY = "conversation.v1"
CONVERSATION_EXTENSION_VERSION = 1
```

The serialized extension is:

```json
{
  "version": 1,
  "session_id": "session-123",
  "mode": "general",
  "bot_id": null,
  "active_message_id": "assistant-002",
  "messages": [
    {
      "id": "user-001",
      "session_id": "session-123",
      "role": "user",
      "content": "Hello",
      "created_at": "2026-09-17T09:00:00+00:00",
      "bot_id": null,
      "references": [],
      "attachments": [],
      "lineage": {
        "supersedes_message_id": null,
        "regenerates_message_id": null
      },
      "metadata": {}
    }
  ]
}
```

Rules:

- `session_id` inside the extension must equal the containing `SharedSessionState.session_id`.
- `version` must equal `1`.
- message IDs must be unique within the extension.
- every message must use the same session ID.
- `active_message_id`, when present, must refer to a stored message.
- `bot_id` is opaque and has no authorization semantics.
- the extension contains public-safe values only.
- the extension does not copy canonical workflow, approval, Domain, memory, knowledge, provider, or execution state.
