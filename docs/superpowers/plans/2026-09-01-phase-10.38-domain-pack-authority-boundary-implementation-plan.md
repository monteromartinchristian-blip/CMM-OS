# Phase 10.38 Domain Pack Authority Boundary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the smallest possible Phase 10.38 trust/authority boundary so that Domain Pack provenance, trust labels, loading, manifest content, and prompt content can never create runtime authority outside the existing canonical permission and approval system.

**Architecture:** Add one immutable trust contract surface and one pure trust evaluator. Integrate the resulting trust ceiling into the existing `DomainPermissionResolver`, and enforce trust before explicit activation in the existing `DefaultDomainAPI`. Reuse canonical discovery, validation, loader, registry, permission, approval, operation, workflow, and security infrastructure. Do not create a trust registry/store, security engine/runtime, new loader, new scanner, new approval system, or Phase 11 hardening infrastructure.

**Tech Stack:** Python 3.12+, frozen dataclasses, `Enum`, `MappingProxyType`, pytest, Ruff, existing CMM OS Domain contracts, canonical Domain validation, canonical Domain loader, canonical permission resolver/gate, canonical approval service and operation orchestration.

**Spec:** `docs/superpowers/specs/2026-09-01-phase-10.38-domain-pack-authority-boundary-design.md`

**Plan baseline:** `124fb02b3eeb03535bd546bc68adb7c2fe328f87`

## Global Constraints

- Phase 10.38 is **not** a global hardening phase.
- Keep the implementation small enough that Phase 11 remains the owner of platform-wide security.
- Preserve exactly:

```text
DISCOVERY != TRUST
TRUST != AUTHORITY
LOAD != ENABLE
INSTALL != AUTHORIZATION
PROMPT != POLICY
CONTENT != AUTHORITY
PERSISTED STATE != CURRENT AUTHORIZATION
```

- `DeclarativeDomainLoader` remains the only Domain loader.
- `PipelineDomainValidator` remains the only Domain validation pipeline.
- `DomainSecurityValidator` and `cmm/domains/validation_security.py` remain the Domain Pack static security scanner.
- `DomainPermissionResolver` and `DomainPermissionGate` remain the authorization owners.
- `ApprovalService` remains the approval owner.
- `DefaultDomainOperationOrchestrator` remains the operation execution owner.
- Existing workflow infrastructure remains the workflow owner.
- `DomainRegistry` remains the Domain lifecycle registry.
- `DefaultDomainAPI` remains the stable Domain facade.
- `allow_untrusted=True` means only explicit permission to load/register an untrusted candidate. It never means enablement or authorization.
- A trust decision may **deny**, **constrain**, or **require explicit activation**. It may never create an ALLOW that the canonical permission system did not already provide.
- Trust-layer permission integration must use existing `PermissionLayerEvaluation` and `intersect_permission_layers`; do not create another permission evaluator.
- Existing source `trusted: bool` is evidence, not authority.
- A manifest `signature` is presence evidence only in this phase. Do not cryptographically verify it unless an already-existing canonical verifier is discovered.
- No signature PKI, key management, certificate infrastructure, SBOM, supply-chain service, container/process sandbox, RBAC, user authentication, secrets manager, network sandbox, or global audit platform.
- Do not create:

```text
DomainSecurityEngine
DomainSecurityRuntime
DomainSecurityStore
DomainSecurityRegistry
DomainTrustStore
DomainTrustRegistry
DomainSecurityLoader
DomainSecurityEventBus
DomainSecurityTraceStore
```

or semantic equivalents.

- Do not implement Phase 10.39 `DomainArchitectureGuard`.
- Do not add a Domain Event for 10.38.
- Preserve the existing Domain Event catalog exactly.
- Keep Phase 10.37 observability read-only.
- No public API convenience method is added merely for trust administration.
- No trust policy persistence is added.
- Every new public contract is immutable, strict, JSON-safe, round-trippable, rejects unknown fields, and deeply freezes caller-owned metadata.
- Unknown or missing required trust evidence fails closed.
- No error or decision payload may include secrets, raw prompt content, traceback text, or arbitrary object `repr()`.
- Every production behavior must begin with a focused RED test.
- If a test that only preserves already-existing behavior is GREEN immediately, record it as a regression proof and do not manufacture a production change.
- Do not modify unrelated closed-phase code.
- No `push` or `merge`.
- Do not use `git stash`, `stash pop`, `stash apply`, `stash drop`, `git reset`, `git clean`, or `git worktree`.
- Preserve the quarantine stash exactly.

## Contract shape

Add exactly this enum to the canonical Domain enum owner:

```python
class DomainTrustLevel(str, Enum):
    TRUSTED = "trusted"
    VERIFIED = "verified"
    INTERNAL = "internal"
    COMMUNITY = "community"
    UNTRUSTED = "untrusted"
    BLOCKED = "blocked"
```

Do not infer numeric authority from enum order.

Implement a frozen trust policy with this semantic shape:

```python
@dataclass(frozen=True, slots=True)
class DomainTrustPolicy:
    domain_id: str
    trust_level: DomainTrustLevel
    authorized_source_ids: tuple[str, ...] = ()
    allow_code_execution: bool = False
    allow_external_access: bool = False
    allow_memory_write: bool = False
    allow_sensitive_resources: bool = False
    allow_destructive_operations: bool = False
    require_manual_enable: bool = True
    require_signature: bool = False
    metadata: Mapping[str, Any] = field(default_factory=dict)
```

Implement a frozen decision contract with one meaning only: evidence from the trust boundary.

```python
@dataclass(frozen=True, slots=True)
class DomainTrustDecision:
    domain_id: str
    candidate_id: str
    source_id: str
    trust_level: DomainTrustLevel
    activation_allowed: bool
    manual_enable_required: bool
    denied_capabilities: tuple[str, ...] = ()
    reason_codes: tuple[str, ...] = ()
    metadata: Mapping[str, Any] = field(default_factory=dict)
```

`denied_capabilities` contains canonical `PermissionCapability.value` strings only.

`activation_allowed=True` does **not** mean runtime permission ALLOW.

### Contract invariants

- strict booleans; no truthy coercion;
- non-empty normalized string IDs;
- `authorized_source_ids` unique and deterministic;
- duplicate source IDs normalize deterministically or fail according to the established Domain contract pattern; use the repository-consistent behavior and lock it with tests;
- `blocked` policy can exist as a valid declaration but never implies activation;
- metadata deeply frozen and JSON-safe;
- `to_dict()` / `from_dict()` round-trip;
- unknown serialized fields rejected;
- invalid trust-level string rejected;
- invalid nested metadata rejected;
- decision cannot claim `activation_allowed=True` while carrying an activation-blocking reason code;
- decision reason codes are stable strings only;
- no raw prompt/content field exists.

- Does not mutate anything.

## Public pure function

Implement:

```python
def evaluate_domain_trust(
    *,
    candidate: DomainCandidate,
    manifest: DomainManifest,
    validation: DomainValidationResult,
    policy: DomainTrustPolicy,
    manual_enable_requested: bool,
) -> DomainTrustDecision:
    ...
```

No filesystem, network, clock, registry, loader, approval, or runtime access is permitted inside this function.

## Activation rules

Evaluate in deterministic order and collect stable reason codes.

### Identity

Fail activation if:

```text
policy.domain_id != candidate.domain_id
validation.domain_id != candidate.domain_id
validation.version != candidate.detected_version
manifest identity/version does not match candidate identity/version
```

Use actual committed manifest identity fields discovered in Task 0.

Reason:

```text
trust.validation_failed
```

Do not create a new identity authority.

### Validation

Fail activation if:

```text
validation.status not PASSED/WARNING
blocking validation finding exists
security_valid is false
```

Reason:

```text
trust.validation_failed
```

Trust never overrides a canonical validation failure.

### Blocked

If:

```python
policy.trust_level is DomainTrustLevel.BLOCKED
```

then:

```text
activation_allowed=False
reason includes trust.blocked
```

even if `candidate.trusted=True`.

### Authorized source

If:

```python
candidate.source_id not in policy.authorized_source_ids
```

then fail with:

```text
trust.source_not_authorized
```

An empty authorized-source tuple authorizes no source.

`candidate.trusted=True` must not bypass this rule.

### Signature-presence policy

If:

```python
policy.require_signature is True
```

and the canonical manifest signature is missing/empty after manifest normalization:

```text
activation_allowed=False
reason includes trust.signature_required
```

If a signature string is present, this check passes **presence only**.

Do not:
- verify a cryptographic signature;
- parse certificates;
- fetch keys;
- add key storage;
- claim `verified` from signature presence.

### Manual enablement

If:

```python
policy.require_manual_enable is True
manual_enable_requested is False
```

fail with:

```text
trust.manual_enable_required
```

The explicit `DefaultDomainAPI.enable_domain(...)` call will later provide `manual_enable_requested=True`.

### Runtime ceilings

Populate `denied_capabilities` deterministically from the policy.

Use canonical existing `PermissionCapability` values.

When `allow_code_execution=False`, deny at minimum:

```text
operation.execute
workflow.execute
```

When `allow_external_access=False`, deny the existing canonical equivalents of:

```text
search.external
model.external
communication.external
export
domain.cross_access
```

Use exact current enum values; do not add enum members.

When `allow_memory_write=False`, deny:

```text
memory.write
```

When `allow_sensitive_resources=False`, deny:

```text
inference.sensitive
sensitive_inference.persist
```

and, when a permission request later carries a canonical sensitivity level other than `public`, the permission-ceiling helper in Task 3 must deny sensitive resource access rather than invent another sensitivity scheme.

When `allow_destructive_operations=False`, deny the existing canonical mutating/high-impact capabilities that already map to destructive/external mutation authority, including only enum members that actually exist at the implementation HEAD:

```text
file.modify
task.create
schedule.modify
goal.update
publication
knowledge.delete
permission.modify
irreversible.change
medical.action
legal.action
financial.action
financial.spend
```

Do not add capabilities merely to make this list symmetrical.

A denied capability does not itself make activation fail. It constrains runtime authority.

### Safe low-trust behavior

`community`, `untrusted`, and `blocked` must remain restrictive through safe defaults.

There is no implicit rule that changes a caller-supplied `allow_*` value based only on enum order.

The policy declaration is explicit; the constructor defaults are restrictive.
