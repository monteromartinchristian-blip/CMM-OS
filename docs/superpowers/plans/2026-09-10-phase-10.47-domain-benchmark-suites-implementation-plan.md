# Phase 10.47 — Domain Benchmark Suites Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement Phase 10.47 as a portable, model-agnostic Domain benchmark asset layer: immutable benchmark contracts, deterministic export/digest, canonical `DomainDefinition`/Domain Pack integration, and representative first-party suites for every currently implemented Domain Pack, without creating a benchmark runtime, model-selection layer, or Phase 10.48 quality metrics.

**Architecture:** Benchmarks are declarative Domain Pack assets owned by `DomainDefinition.benchmark_suites`. Shared contracts live in `cmm/domains/benchmark_contracts.py`; each first-party domain owns its own `benchmarks.py`; the existing DomainDefinition/Domain Pack/DomainRegistry path remains the single source of truth. Phase 10.47 validates, serializes, exports and discovers benchmark assets only; Phase 10.48 owns weighted quality metrics and Phase 11.36 owns model execution/comparison.

**Tech Stack:** Python 3, frozen/slotted dataclasses, `Decimal`, canonical JSON, SHA-256, existing CMM OS Domain contracts/pack/registry infrastructure, pytest, Ruff.

**Spec:** `docs/superpowers/specs/2026-09-10-phase-10.47-domain-benchmark-suites-design.md`

**Required starting branch:** `feature/phase-10-domain-intelligence`

**Required starting HEAD for implementation execution:** the exact commit that records this implementation plan. Do **not** start implementation from the spec commit; the agent prompt must resolve and pin the plan commit HEAD.
