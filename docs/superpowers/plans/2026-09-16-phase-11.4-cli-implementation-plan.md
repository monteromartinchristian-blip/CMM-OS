# Phase 11.4 — CLI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Consolidate the existing CMM OS command-line surfaces behind the one public `cmm` front door, add a stable presentation/error/exit-code contract, make `status`, `doctor`, `ask`, and `chat` operational through the canonical Application Backend, reserve the complete Phase 11.4 roadmap namespace with fail-closed unavailable behavior, preserve all inherited CLI subtrees, and prove the result through `AT-DP-104`.

**Architecture:** Preserve `cmm = "cmm.cli:main"` and the existing `cmm.__main__` `argparse` root. Add small presentation-only CLI modules beside `cmm/cli.py`; use `ApplicationGateway` for application-facing commands, existing specialized Validation/Domain SDK/Agent Runtime facades for inherited subtrees, and a canonical application-layer local composition factory for standalone CLI startup. No command registry, command router, CLI runtime, parallel store, or missing platform subsystem may be introduced.

**Tech Stack:** Python 3.10+, `argparse`, standard library `json`, `PyYAML>=6.0,<7` for YAML, existing `cmm.application` / `cmm.platform` / `cmm.orchestration` contracts, pytest 9, Ruff.

```python
class ApplicationChannel(str, Enum):
    API = "api"
    CLI = "cli"
```


HTTP adapters do not need to change because requests default to API.

Map `ApplicationErrorCode` to `CliExitCode` exactly:

```text
INVALID_REQUEST           -> INVALID_REQUEST (3)
UNSUPPORTED_VERSION       -> INVALID_REQUEST (3)
POLICY_DENIED             -> PERMISSION_DENIED (6)
RESOURCE_NOT_FOUND        -> NOT_FOUND (4)
CONFLICT                  -> CONFLICT (7)
IDEMPOTENCY_CONFLICT      -> CONFLICT (7)
CONCURRENCY_CONFLICT      -> CONFLICT (7)
APPROVAL_REQUIRED         -> PERMISSION_DENIED (6)
CANCELLED                 -> CANCELLED (9)
CAPABILITY_UNAVAILABLE    -> CAPABILITY_UNAVAILABLE (5)
INTERNAL_FAILURE          -> INTERNAL_FAILURE (10)
```

Success:

```text
ApplicationStatus.SUCCESS -> SUCCESS (0)
```

Doctor:

```text
any required/core FAIL -> DEPENDENCY_UNHEALTHY (8)
no required/core FAIL  -> SUCCESS (0)
```

`UNAVAILABLE` for future/non-core doctor checks does not by itself make doctor
exit non-zero.

```text
API
```

CLI explicitly sets:

```text
CLI
```

No direct CLI-to-Orchestrator call is introduced.

Standalone CLI startup requires a real canonical ApplicationGateway.

The plan therefore extracts the already-proven AT-DP-103 official/in-memory
composition into:

```text
cmm.application.local_runtime
```

This is a composition helper, not a new owner.

It must remain side-effect-bounded and local.

```text
status
doctor
ask
chat
```

are newly operational in Phase 11.4.

All other new roadmap namespaces are deliberately reserved but unavailable.

This is the user-approved fail-closed strategy and avoids building later-phase
subsystems inside the CLI.
